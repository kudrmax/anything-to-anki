# Коллекции и подколлекции

Решения согласованы с Максом 14.10.2026.

## Цель

Источники раскладываются по двухуровневому дереву: коллекция → подколлекция. Работа с деревом — на уровне современных приложений (Finder, Notion, Things): ручной порядок, drag & drop, мультивыбор, Undo вместо подтверждений.

Сценарии:

- IELTS → «Тема X» → тексты;
- Друзья → «Сезон 1» → серии;
- Worm → тексты прямо в коллекции;
- Worm → главы прямо в коллекции + подколлекция «Доп. главы».

## Термины

- **Коллекция** — узел верхнего уровня.
- **Подколлекция** — узел, у которого есть родитель. Глубже подколлекции дерево не растёт.
- **Unsorted** — источники без коллекции.
- **Область (scope)** — то, что открыто на экране: All, Unsorted или узел дерева. Область узла включает его поддерево: в «Друзьях» видны и серии сезонов.
- **Стадия** — группа источника в списке: In progress, Preparing, Ready to review, Reviewed.

## Модель

`Collection` (domain entity):

- `name`;
- `parent_id: int | None` — родитель; родителем может быть только коллекция верхнего уровня;
- `position: int` — ручной порядок среди соседей (узлов с тем же родителем);
- `deleted_at: datetime | None` — мягкое удаление ради Undo.

Источник лежит не более чем в одном узле (`sources.collection_id`, как сейчас) — в коллекции или в подколлекции.

Правила домена:

- глубина не больше двух уровней;
- имя уникально среди неудалённых соседей без учёта регистра и пробелов по краям; «Сезон 1» может быть и у Друзей, и у Lost;
- новый узел встаёт в конец соседей.

Миграция (Alembic): `parent_id`, `position`, `deleted_at`; глобальная уникальность имени заменяется уникальностью среди соседей. Существующие коллекции становятся верхним уровнем, `position` — по текущему алфавиту.

## Use case'ы

| Use case | Что делает |
|---|---|
| `CreateCollection(name, parent_id?)` | Создаёт узел в конце соседей |
| `RenameCollection(id, name)` | Проверяет уникальность среди соседей |
| `MoveCollection(id, parent_id?, position)` | Перенос к другому родителю и ручная сортировка одной операцией |
| `DeleteCollection(id)` | Мягкое удаление, см. ниже |
| `RestoreCollection(id)` | Undo удаления |
| `MoveSources(source_ids, collection_id?)` | Перенос пачкой; возвращает прежнее размещение |
| `ListCollections()` | Дерево в ручном порядке со счётчиками |
| `GetSources(scope, query?)` | Источники области, разложенные по стадиям |
| `ProcessPending(scope)` | Запускает обработку необработанных источников области |

`AssignSourceToCollection` заменяется `MoveSources`.

### MoveCollection

Запрещено:

- переносить узел в себя;
- переносить коллекцию, у которой есть подколлекции, внутрь другой коллекции;
- переносить узел внутрь подколлекции.

Коллекция без подколлекций, перенесённая в другую, становится подколлекцией. Подколлекция, перенесённая на верхний уровень, становится коллекцией.

### Удаление

- Подколлекция: её источники поднимаются в родителя.
- Коллекция: источники всего поддерева уходят в Unsorted, подколлекции удаляются.

Удаление мягкое: прежнее размещение каждого источника запоминается. `RestoreCollection` возвращает узел, его подколлекции и источники точно на места. Источники, которые после удаления перенесли вручную, Restore не трогает.

Источники при удалении коллекции не удаляются никогда.

Если за время после удаления у соседей появился узел с тем же именем, Restore отказывает с понятной ошибкой.

### Undo для переноса и переименования

`MoveSources` возвращает прежний `collection_id` каждого источника, `MoveCollection` — прежние `parent_id` и `position`, `RenameCollection` — прежнее имя. Undo — повторный вызов того же use case'а с этим ответом. Решение «куда вернуть» принимает backend: фронт только передаёт его ответ обратно.

### Счётчики дерева

Для каждого узла, по поддереву:

- всего источников;
- разобрано (статус Reviewed);
- ждёт обработки (то, что запустит «Process all»).

Для All и Unsorted — те же счётчики.

### GetSources

- Область: `all`, `unsorted` или `collection_id` (с поддеревом).
- Стадию источника вычисляет backend. `stageOf`, `isPending`, `pendingCount` и фильтр по коллекции уходят из фронта.
- Внутри стадии — новые сверху.
- У источника есть путь узла (`Друзья / Сезон 1`) для подписи в строке.
- `query` — поиск по названию источника, без учёта регистра.

### ProcessPending

Заменяет цикл `processAll` во фронте. Обрабатывает только область, открытую на экране. Исправляет баг: «Process all» в коллекции запускал все необработанные источники приложения.

### Экспорт по области

Экран Export получает ту же область: можно выгрузить в Anki только IELTS или только «Друзья / Сезон 1». Выгрузка «всё» и «один источник» остаются.

### Книги

Как сейчас: книга создаёт коллекцию верхнего уровня (в конце списка) или дописывает главы в существующую коллекцию верхнего уровня с тем же именем.

## Экран Sources

### Навигация

- Вкладки: **Add** (перед Sources), Sources, Export, Queue, Usage. Add ведёт на существующий экран `/add`; форма добавления уходит с экрана Sources.
- Добавление не зависит от открытой области: обычный источник попадает в Unsorted.
- Файл, который тащат над экраном Sources, сразу открывает Add; бросается он уже туда.
- Открытая область живёт в URL: `/?scope=12`, `/?scope=unsorted`; All — без параметра. Несуществующий узел в URL открывает All. После Review возвращаешься туда же; ссылку на коллекцию можно открыть напрямую.

### Левая колонка

Сверху статистика (to learn, known words, candidates), под ней дерево:

- All, Unsorted, затем коллекции в ручном порядке;
- счётчик у узла — по поддереву;
- «+» у заголовка Collections создаёт коллекцию, имя вводится в дереве;
- переименование — двойной клик или F2; Enter сохраняет, Esc отменяет;
- свёрнутость веток запоминается между сессиями (локальное состояние экрана);
- правый клик по узлу открывает то же меню, что «⋯» в шапке.

Drag & drop в дереве:

- узел между соседями — ручная сортировка;
- коллекция на коллекцию — становится подколлекцией;
- подколлекция на верхний уровень — становится коллекцией;
- запрещённая цель не подсвечивается.

### Шапка области

- Хлебные крошки: `Друзья › Сезон 1`.
- Прогресс: «4 из 8 разобрано».
- **Process all (N)** — только если есть что обрабатывать.
- **Export** — открывает Export с этой областью.
- **⋯**: Rename, New subcollection (только у коллекции), Move to…, Delete.

### Список

- Группы по стадиям во всех областях.
- В строке источника мелко — путь узла, если источник лежит не прямо в открытом узле.
- Поиск по названию в пределах области.
- Пустой узел: «Drag sources here or use Move to…».

Мультивыбор, как в Finder:

- Cmd-клик — добавить или убрать из выбора;
- Shift-клик — диапазон;
- Cmd-A — всё в области; Esc — снять выбор.

Панель выбора внизу: Move to…, Process, Delete.

Перенос источников:

- перетащить один или выбранные на узел дерева, в том числе на Unsorted;
- «Move to…» — список узлов с поиском. Основной путь на телефоне и с клавиатуры.

### Undo

Перенос источников, перенос узла, переименование и удаление коллекции применяются сразу и показывают тост с Undo (~6 секунд), например «Moved 2 sources to Сезон 2 · Undo». Cmd-Z — то же самое.

Удаление источников остаётся с подтверждением: оно необратимо.

### Ошибки

Ни одна ошибка не глотается. Ответ backend'а показывается тостом понятным текстом: «Collection "Сезон 1" already exists here».

### Телефон

- Левая колонка складывается в селектор области над списком; тап открывает лист снизу с деревом и статистикой.
- Drag & drop нет. Долгий тап включает выбор, дальше «Move to…».

## Исправляемые баги

1. «Process all» в открытой коллекции запускал все необработанные источники приложения.
2. Ошибки создания, переименования и переноса коллекций молча глотались (`catch { // ignore }`), включая 409 на занятое имя.
3. Открытая коллекция сбрасывалась на All после возврата из Review.
4. Бизнес-логика списка жила во фронте: фильтр по коллекции, стадии, «ожидает обработки».

## Вне рамок

- Иконки и эмодзи у коллекций.
- Архив коллекций — отдельная задача.
- Отдельные колоды Anki по коллекциям.
- Глубина больше двух уровней.
