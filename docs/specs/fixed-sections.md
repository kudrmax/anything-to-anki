# Ready не пополняется во время разметки

Issue: https://github.com/kudrmax/anything-to-anki/issues/2. Решения Макса 19–20.10.2026.

## Проблема

Секция карточки (Ready / Extra / Probably known) считается при каждом чтении (`candidate_sections.section_of`) по текущему знанию и порогу частотности. Поэтому, пока пользователь размечает карточки, в Ready сами появляются новые: пометил Known слово в другом источнике, истёк таймер Learning, подстроился порог Auto — фраза стала «только target новый», карточка приехала в Ready, счётчик вырос, закрытый источник открылся.

## Принцип

**Разметка не добавляет карточки в Ready, только убирает. Пополняет Ready только Rebuild.**

- **Разметка** — решения о словах: Known, Learn, Skip, жалоба на незнакомые слова, правка списков Known и Unknown. **Само** — таймер Learning, порог Auto. От них карточка может уйти из Ready, но не появиться в нём.
- **Rebuild** пересчитывает Ready полностью, в обе стороны.
- **Смена уровня CEFR и смена настройки порога частотности** запускают Rebuild всех источников. Отдельного пересчёта для настроек нет.
- **Собственный текст фразы** (новая фраза, Polish, правка) даёт ей секцию по этому тексту — в обе стороны.
- Логика секций не смотрит на meaning и прочую генерацию.

## Решение

**Заработанная секция** — секция, которую фраза получает по своему показанному тексту (`section_of`, правило вычисления не меняется): Ready, Extra или Probably known.

1. Заработанная секция хранится на каждой фразе: `phrases.earned_section` (`ready` | `extra` | `probably_known`). Её ставят:
   - каждая запись новой фразы и каждая запись её текста (`OccurrenceRepository.add` / `write_text`, строки Rebuild-плана): обработка источника, Rebuild, Replace with example, ручное добавление, фразы темы, Refresh темы (новые фразы), Saved phrases; Polish готов, Polish отменён или сброшен, ручная правка, ручная граница, Rebuild переписал текст;
   - Rebuild — у каждой фразы источника без выбора (Learn / Cloze / Known / Skip) и не в Anki, в итоговом состоянии плана. Добавлена ли фраза пользователем, роли не играет: секция — не работа пользователя. У фразы с выбором или в Anki Rebuild секцию не меняет.
2. **Где стоит открытая карточка** — текущая секция её фразы (`section_of` по знанию сейчас), с одним ограничением: **в Ready карточка стоит, только если и текущая, и заработанная секции — Ready.** Если текущая — Ready, а заработанная — нет, карточка стоит в заработанной. Done-карточка — в Reviewed, как сейчас.
3. Следствия, без отдельных правил:
   - жалоба на незнакомые слова, снятие Known — карточки с этими словами уходят из Ready сразу, во всех источниках;
   - Known на другом слове, таймер, порог Auto, удаление слова из Unknown — карточка в Ready не приходит и не возвращается до Rebuild;
   - переходы между Extra и Probably known идут по текущему знанию, как сейчас;
   - снял Known (или Learn) — слово NEW везде, его done-карточки открываются и встают по п. 2;
   - «✨ для Ready», счётчик прогресса и статус разбора источника читают секцию по п. 2.
4. Порядок внутри секции — по текущему знанию, как сейчас.

### Смена настроек

Сохранение другого уровня CEFR или другой настройки порога частотности (`manage_settings`) после записи запускает Rebuild (`include_open=False`) каждого источника, которому Rebuild доступен, — тем же путём, что кнопка Rebuild. Источник, занятый другой операцией, пропускается и остаётся до своего Rebuild. Порог Auto, подстроившийся сам, Rebuild не запускает.

### Rebuild у темы и Saved phrases

У источников без своего текста (тема, Saved phrases) Rebuild нет (`RebuildNotSupportedError`). Они его получают — отдельной операцией, рядом с Refresh темы: Refresh только добирает фразы, Rebuild только пересчитывает.

- `available_operations` возвращает набор операций: у темы — Refresh и Rebuild, у Saved phrases — Rebuild, у источника со своим текстом — Rebuild.
- У источника без своего текста Rebuild не анализирует: план — только изменения заработанных секций по п. 1. Переключатель «Also unreviewed cards» у него не показывается.
- То же окно Rebuild и то же превью, без новых счётчиков и текстов.

## Вне этой задачи

Сейчас слово, которое пользователь учит, считается незнакомым в других фразах (`UserKnowledge.is_new`), поэтому Learn на слове уводит из Ready чужие карточки с ним. Макс назвал это неправильным; это правило знания, а не секций, — отдельный issue. Здесь оно не меняется.

## Существующие данные

В приложении никакой логики для старых данных нет.

- Миграция `0050` добавляет колонку `phrases.earned_section` (NULL-able до скрипта).
- Разовый скрипт `make fix-sections` при остановленном приложении: миграции, `section_of` каждой фразе без секции, затем Rebuild (`include_open=False`) каждого источника, которому он доступен.
- Обновление в этот раз: `git pull && make down && make fix-sections && make up` — в dev и в prod. Скрипт прогоняю я.
- Фраза без секции — ошибка чтения с подсказкой запустить `make fix-sections`.

## Модель

- `Occurrence.earned_section: CandidateSection` (без REVIEWED).
- Домен: `section_of` без изменений; новое правило п. 2 — одна функция в `card_view.py` (`shown_section(current, earned)`), которую читают список, прогресс и «✨ для Ready».
- `SectionStamper` (application) — заработанная секция по текущему знанию и порогу; его используют все записи из п. 1.
- Rebuild-план: `SectionChange` для фраз без выбора и не в Anki; `RebuildPlan.is_empty` их учитывает.
- `ManageSettings` получает зависимость, которая запускает Rebuild всех источников (через DI).

## Тесты

- Known на другом слове, таймер, порог Auto, удаление из Unknown — открытая карточка не приходит в Ready.
- Жалоба на незнакомые слова — все карточки с этим словом уходят из Ready во всех источниках.
- Rebuild приводит Ready к текущему знанию в обе стороны; у фразы с выбором или в Anki заработанная секция не меняется.
- Смена уровня и смена порога запускают Rebuild всех источников; занятый источник пропускается; подстройка Auto Rebuild не запускает.
- Polish, его отмена и сброс, правка, граница пересчитывают заработанную секцию фразы.
- Rebuild темы и Saved phrases меняет только секции; Refresh секций не трогает.
- `make fix-sections` на копии prod-БД: у всех фраз есть секция, решения и сгенерированное не изменились.
