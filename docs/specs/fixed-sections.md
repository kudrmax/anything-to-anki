# Секция карточки фиксируется

Issue: https://github.com/kudrmax/anything-to-anki/issues/2. Решения Макса 19.10.2026.

## Проблема

Секция карточки (Ready / Extra / Probably known) сейчас не хранится, а считается при каждом чтении (`candidate_sections.section_of`) по текущему знанию пользователя и порогу частотности. Поэтому карточки переезжают между секциями без действий пользователя над ними:

1. Пользователь пометил Known другое слово фразы, в любом источнике, — фраза теряет незнакомое слово и переезжает Extra → Ready.
2. Таймер Learning (30 дней) сделал слово Known — то же самое, совсем без действия.
3. Порог частотности Auto калибруется на каждом Learn/Known — карточки переезжают в Probably known и обратно.

Extra не генерируется (генерация «только Ready»), поэтому карточка приезжает в Ready без meaning. Полностью разобранный источник снова показывает открытые карточки, счётчик прогресса падает.

## Решение

**Заработанная секция** — секция, которую фраза получает по своему показанному тексту: Ready (новый только target), Extra (новы и другие слова фразы), Probably known (target частотный или мусор). Правило вычисления то же, `section_of`; меняется только момент вычисления.

1. Заработанная секция хранится на каждой фразе, показанной или нет: `phrases.earned_section` (`ready` | `extra` | `probably_known`).
2. Она вычисляется по знанию и порогу на тот момент, когда **у фразы появляется строка или меняется показанный текст**. Правило одно: секцию ставит каждая запись новой фразы и каждая запись её текста (`OccurrenceRepository.add` / `write_text` и строки Rebuild-плана), `earned_section` — обязательный аргумент, так что пропущенный путь ловит mypy. Сейчас это:
   - новая фраза: обработка источника, Rebuild, Replace with example, ручное добавление, фразы темы, Refresh темы (новые фразы), Saved phrases;
   - текст: Polish готов, Polish отменён или сброшен (новый Polish, discard, ответ без target), ручная правка фразы, ручная граница, Rebuild переписал текст.
3. **Rebuild** пересчитывает её у каждой фразы источника без выбора (Learn / Cloze / Known / Skip) и не в Anki — в итоговом состоянии плана, после вставок, правок текста и отбора. Добавлена ли фраза пользователем или им поправлена, роли не играет: секция — не работа пользователя, текст и генерацию Rebuild у таких фраз по-прежнему не трогает. У фразы с выбором или в Anki секция не меняется.
4. Ничто другое секцию не меняет: Known/Learn на других словах, таймер, калибровка, смена настройки порога, смена настройки уровня CEFR.
5. Где карточка стоит = Reviewed, если она done (как сейчас, `card_view.is_done`), иначе её заработанная секция. Done по-прежнему считается живьём: решение пользователя двигает карточку сразу.

Следствия, без новых правил:
- Пользователь снял Known (или Learn) — слово NEW везде, его карточки перестают быть done и встают в свою заработанную секцию. Meaning для Ready пользователь делает кнопкой ✨ «сгенерировать Ready», как у любой карточки Ready.
- Polish запускается для Ready; если он вставил незнакомое слово, карточка уходит в Extra — по действию пользователя.
- «✨ для Ready», счётчик прогресса и статус разбора источника читают заработанную секцию — сами они тоже больше не меняются.

### Порядок внутри секции

Сортировка внутри секции (relevance, key words) по-прежнему использует текущее знание (`new_words`). Разбиение на секции в сортировке (`candidate_sorting`) берёт заработанную секцию. Между секциями карточки не переезжают, внутри секции порядок может сдвинуться.

### Rebuild у темы и Saved phrases

У источников без своего текста (тема, Saved phrases) Rebuild нет (`RebuildNotSupportedError`, у `SourceRebuilder.analyse` — `SourceHasNoDocumentError`). Они его получают — отдельной операцией, рядом с Refresh темы: Refresh по-прежнему только добирает фразы из других источников, Rebuild — только пересчитывает.

- `available_operation` возвращает набор операций источника: у темы — Refresh и Rebuild, у Saved phrases — Rebuild, у источника со своим текстом — Rebuild, как сейчас.
- У источника без документа Rebuild пропускает анализ: план — только изменения секций по п. 3. Фразы, слова и генерацию не трогает. Переключатель «Also unreviewed cards» у него не показывается: переписывать нечего.
- То же окно Rebuild и то же превью.

## Существующие данные

В приложении никакой логики для старых данных нет.

- Миграция `0050` добавляет колонку `phrases.earned_section` (NULL-able: значения у старых фраз появятся только после скрипта).
- Разовый скрипт `scripts/fix_sections.py` через `make fix-sections` (с `_check_setup dict-update`, как у `migrate-paths`; читает `.env` своей копии) при остановленном приложении:
  1. прогоняет миграции;
  2. ставит `section_of` каждой фразе без секции;
  3. делает Rebuild (`include_open=False`) каждого источника, которому Rebuild доступен (`available_operation`).
- Порядок обновления в этот раз: `git pull && make down && make fix-sections && make up` — в dev и в prod. Скрипт прогоняю я.
- Приложение считает секцию обязательной: фраза без неё — ошибка чтения с подсказкой запустить `make fix-sections`, не тихий пересчёт.

## Модель

- `Occurrence.earned_section: CandidateSection` (без REVIEWED; конструктор отвергает REVIEWED).
- Домен: `candidate_sections.section_of` без изменений. `ShownCardFacts` получает `earned_section`; `card_section(card)` берёт его вместо пересчёта. `ReviewCard` отдаёт секцию своей фразы, `CardRow` (прогресс) — из колонки, которую выбирает `SqlaCardQuery`.
- Приложение: `SectionStamper` (`application/utils`, через `container.py`) по `UserKnowledgeReader` и `FrequentWordThresholdResolver` возвращает заработанную секцию фразы. Его используют все пути из п. 2 (в т.ч. `CollectedPhrases`, который сейчас собирается вручную в `AddSavedPhrase`).
- Rebuild: `plan_rebuild` работает на хэшах и текста не видит, поэтому секции считает `SourceRebuilder.apply` в той же транзакции после `apply_plan`, по итоговым фразам; изменение пишется только если значение другое. Превью считает те же изменения, и `RebuildPlan.is_empty` учитывает их — иначе Rebuild, меняющий только секции, скрыт как «нечего обновлять».
- `CandidateSorter`: `arrange`, `section`, `earned_sections`, `progress` больше не читают знание и порог для секции.

## Тесты

- Known на другом слове, истёкший таймер, калибровка, смена порога, смена уровня — секция открытой карточки не меняется.
- Каждая запись текста фразы (Polish, его отмена и сброс, правка, граница) пересчитывает секцию.
- Rebuild пересчитывает секцию фразы без выбора и не в Anki, включая ручную и example, и не трогает фразу с выбором или в Anki; Rebuild, меняющий только секции, не пустой.
- Rebuild темы и Saved phrases пересчитывает только секции; фразы и генерация не меняются; Refresh секций не трогает.
- Меню источника показывает у темы и Refresh, и Rebuild.
- Снятие Known возвращает done-карточку в её заработанную секцию.
- Каждый путь создания фразы пишет секцию.
- `make fix-sections` на копии prod-БД: после него у всех фраз есть секция, решения и сгенерированное не изменились.
