# Секция карточки фиксируется

Issue: https://github.com/kudrmax/anything-to-anki/issues/2. Решения Макса 19.10.2026.

## Проблема

Секция карточки (Ready / Extra / Probably known) сейчас не хранится, а считается при каждом чтении (`candidate_sections.section_of`) по текущему знанию пользователя и порогу частотности. Поэтому карточки переезжают между секциями без действий пользователя над ними:

1. Пользователь пометил Known другое слово фразы, в любом источнике, — фраза теряет незнакомое слово и переезжает Extra → Ready.
2. Таймер Learning (30 дней) сделал слово Known — то же самое, совсем без действия.
3. Порог частотности Auto калибруется на каждом Learn/Known — карточки переезжают в Probably known и обратно.

Extra не генерируется (генерация «только Ready»), поэтому карточка приезжает в Ready без meaning. Полностью разобранный источник снова показывает открытые карточки, счётчик прогресса падает.

## Решение

**Заработанная секция** — секция, которую фраза получает по своему тексту: Ready (новый только target), Extra (новы и другие слова фразы), Probably known (target частотный или мусор). Правило вычисления то же, `section_of`; меняется только момент вычисления.

1. Заработанная секция хранится на фразе: `phrases.earned_section` (`ready` | `extra` | `probably_known`).
2. Она вычисляется по знанию и порогу на тот момент, когда **у фразы появляется текст или меняется показанный текст**:
   - фраза создана: обработка источника, Rebuild, Replace with example, ручное добавление, фразы темы;
   - Polish готов или Polish отменён (`polish_reverted`);
   - Rebuild переписал текст фразы.
3. **Rebuild** пересчитывает её у каждой показанной фразы источника, которая не `is_protected` (нет выбора, не в Anki, нет работы пользователя). У неприкосновенной фразы Rebuild секцию не меняет.
4. Ничто другое секцию не меняет: Known/Learn на других словах, таймер, калибровка, смена настройки порога.
5. Где карточка стоит = Reviewed, если она done (как сейчас, `card_view.is_done`), иначе её заработанная секция. Done по-прежнему считается живьём: решение пользователя двигает карточку сразу.

Следствия, без новых правил:
- Пользователь снял Known (или Learn) — слово NEW везде, его карточки перестают быть done и встают в свою заработанную секцию. Meaning для Ready — кнопкой ✨, как у любой карточки Ready.
- После Polish карточка может переехать Extra ↔ Ready: Polish запускает пользователь. Если у неё нет meaning, ✨ для Ready его делает.
- «✨ для Ready», счётчик прогресса и статус разбора источника читают заработанную секцию — сами они тоже больше не меняются.

### Порядок внутри секции

Сортировка внутри секции (relevance, key words) по-прежнему использует текущее знание (`new_words`). Разбиение на секции в сортировке (`candidate_sorting`) берёт заработанную секцию. Между секциями карточки не переезжают, внутри секции порядок может сдвинуться.

### Rebuild у темы и Saved phrases

Сейчас у источников без своего текста (тема, Saved phrases) Rebuild нет (`RebuildNotSupportedError`). Они его получают: та же кнопка и то же окно. Анализировать у них нечего, поэтому их Rebuild делает только применимое (п. 3): пересчитывает заработанную секцию нетронутых фраз. Фразы, слова и генерацию не трогает. `RebuildNotSupportedError` остаётся только для источника, который ещё ни разу не обработан.

## Существующие данные

В приложении никакой логики для старых данных нет.

- Миграция `0050` добавляет колонку `phrases.earned_section` (NULL-able: значения у старых фраз появятся только после скрипта).
- Разовый скрипт `make fix-sections` при остановленном приложении: прогоняет миграции, делает Rebuild каждого источника, затем ставит заработанную секцию оставшимся фразам без неё (неприкосновенным) по `section_of`. Скрипт лежит в `scripts/`, приложение его не вызывает.
- Порядок обновления в этот раз: `git pull && make down && make fix-sections && make up` — в dev и в prod. Скрипт прогоняю я.
- Приложение считает секцию обязательной: фраза без неё — ошибка чтения с подсказкой запустить `make fix-sections`, не тихий пересчёт.

## Модель

- `Occurrence.earned_section: CandidateSection` (без REVIEWED; конструктор отвергает REVIEWED).
- Домен: `candidate_sections.section_of` без изменений; `card_section(card)` берёт `card.occurrence.earned_section` вместо пересчёта.
- Приложение: `SectionStamper` (`application/utils`) по `UserKnowledgeReader` и `FrequentWordThresholdResolver` возвращает заработанную секцию фразы. Его используют все пути из п. 2 и Rebuild.
- Rebuild-план: шаг `SectionChange(phrase_id, earned_section)` для нетронутых фраз; писатель плана применяет его в той же транзакции.
- `CandidateSorter`: `arrange`, `section`, `earned_sections`, `progress` больше не читают знание и порог для секции.

## Тесты

- Known на другом слове, истёкший таймер, калибровка, смена порога — секция открытой карточки не меняется.
- Polish и его отмена пересчитывают секцию.
- Rebuild пересчитывает секцию нетронутой фразы и не трогает неприкосновенную.
- Rebuild темы и Saved phrases пересчитывает только секции; фразы и генерация не меняются.
- Снятие Known возвращает done-карточку в её заработанную секцию.
- Каждый путь создания фразы пишет секцию.
- `make fix-sections` на копии prod-БД: после него у всех фраз есть секция, решения и сгенерированное не изменились.
