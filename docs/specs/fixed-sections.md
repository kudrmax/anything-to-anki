# Секция карточки фиксируется, двигает её только Rebuild

Issue: https://github.com/kudrmax/anything-to-anki/issues/2. Решение Макса 19.10.2026: вариант 1.

## Проблема

Секция карточки (Ready / Extra / Probably known) сейчас не хранится, а считается при каждом чтении (`candidate_sections.section_of`) по текущему знанию пользователя и порогу частотности. Поэтому карточки переезжают между секциями без действий пользователя над ними:

1. Пользователь пометил Known другое слово фразы, в любом источнике, — фраза теряет незнакомое слово и переезжает Extra → Ready.
2. Таймер Learning (30 дней) сделал слово Known — то же самое, совсем без действия.
3. Порог частотности Auto калибруется на каждом Learn/Known — карточки переезжают в Probably known и обратно.
4. Polish поменял текст фразы — меняется набор её слов, а с ним секция.

Extra не генерируется (генерация «только Ready»), поэтому карточка приезжает в Ready без meaning. Полностью разобранный источник снова показывает открытые карточки, счётчик прогресса падает.

## Решение

**Заработанная секция** — секция, которую фраза получает по своим словам: Ready (новый только target), Extra (новы и другие слова фразы), Probably known (target частотный или мусор). Правило вычисления то же, `section_of`; меняется только момент вычисления.

1. Заработанная секция хранится на фразе: `phrases.earned_section` (`ready` | `extra` | `probably_known`), NOT NULL.
2. Она вычисляется по знанию и порогу **в момент создания фразы**: обработка источника, Rebuild (новые фразы), Replace with example, ручное добавление, фразы темы.
3. Её пересчитывает **только Rebuild**: у каждой показанной фразы источника, которая не `is_protected` (нет выбора, не в Anki, нет работы пользователя), — по знанию и порогу на момент Rebuild. У неприкосновенной фразы секция не меняется.
4. Ничто другое секцию не меняет: Known/Learn на других словах, таймер, калибровка, смена настройки порога, Polish.
5. Где карточка стоит = Reviewed, если она done (как сейчас, `card_view.is_done`), иначе её заработанная секция. Done по-прежнему считается живьём: решение пользователя — его действие, оно двигает карточку сразу.

Следствия, без новых правил:
- Пользователь снял Known (или Learn) — слово NEW везде, его карточки перестают быть done и встают в свою заработанную секцию. Meaning для Ready — кнопкой ✨, как у любой карточки Ready.
- «✨ для Ready», счётчик прогресса и статус разбора источника читают заработанную секцию — они тоже перестают меняться сами.

### Окно Rebuild

`RebuildCounts` получает два счётчика: сколько открытых карточек перейдёт **в Ready** и сколько **уйдёт из Ready**. Окно Rebuild показывает их рядом с остальными, чтобы было видно, есть ли смысл пересобирать.

### Порядок внутри секции

Сортировка внутри секции (relevance, key words) по-прежнему использует текущее знание (`new_words`). Разбиение на секции в сортировке (`candidate_sorting`) берёт заработанную секцию. Карточки не переезжают между секциями, внутри секции порядок может сдвинуться.

## Существующие данные

Миграция `0050` добавляет `phrases.earned_section` NULL-able. При старте приложения, после миграций, шаг `fill_earned_sections` один раз вычисляет секцию всем фразам с NULL по текущему знанию и порогу (как `reconcile_media_files` в `lifespan`). Новых NULL не появляется: все пути создания пишут секцию, тест это проверяет. Секцию старых источников фиксирует знание на момент первого запуска после обновления.

## Модель

- `Occurrence.earned_section: CandidateSection` (без REVIEWED; конструктор отвергает REVIEWED).
- Домен: `candidate_sections.section_of` без изменений; `card_section(card)` берёт `card.occurrence.earned_section` вместо пересчёта.
- Приложение: `SectionStamper` (`application/utils`) — один объект, который по `UserKnowledgeReader` и `FrequentWordThresholdResolver` возвращает заработанную секцию фразы. Его используют все пути создания и Rebuild.
- Rebuild-план: новый шаг `SectionChange(phrase_id, earned_section)` для нетронутых фраз; писатель плана применяет его в той же транзакции.
- `CandidateSorter`: `arrange`, `section`, `earned_sections`, `progress` больше не читают знание и порог для секции.

## Тесты

- Known на другом слове, истёкший таймер, калибровка, смена порога, Polish — секция открытой карточки не меняется.
- Rebuild пересчитывает секцию нетронутой фразы и не трогает неприкосновенную; счётчики «в Ready» / «из Ready» в превью.
- Снятие Known возвращает done-карточку в её заработанную секцию.
- Каждый путь создания фразы пишет секцию (нет NULL).
- Rebuild темы и Saved phrases пересчитывает только секции, фразы и генерация не меняются.
- `fill_earned_sections` заполняет только NULL и идемпотентен.
- Тест миграции на копии prod-БД (как для 0049).

### Rebuild у темы и Saved phrases

Сейчас у источников без своего текста (тема, Saved phrases) Rebuild нет (`RebuildNotSupportedError`). Они его получают: та же кнопка и то же окно. Анализировать у них нечего, поэтому их Rebuild делает только применимое — пересчитывает заработанную секцию нетронутых фраз (п. 3). Фразы, слова и генерацию не трогает. `RebuildNotSupportedError` остаётся только для источника, который ещё ни разу не обработан.
