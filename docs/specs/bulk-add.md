# Несколько файлов за раз и окно названий

Решения Макса 20.10.2026. Issue: https://github.com/kudrmax/anything-to-anki/issues/8

## Проблема

Кейс: на ноуте лежат 10 глав одной книги отдельными файлами с плохими именами (`Atomic_Habits_FINAL(2)_05_scan.txt`, `ah-06 v2.txt`). Сейчас их можно добавить только по одному, и каждый источник получает имя файла. Переименовывать файлы на диске пользователь не хочет — названия задаются в приложении.

## Принцип

1. **Несколько файлов — это несколько обычных добавлений за раз.** Каждый файл проходит свой обычный путь со своим типом: статья остаётся статьёй, песня песней, epub — epub. Никакой «книги из файлов».
2. **Общее у пачки файлов и разбитого epub — группа источников из одного добавления.** Если добавление даёт два источника и больше, перед созданием открывается одно и то же **окно названий**: коллекция и правило названий.
3. **Добавление, которое даёт один источник, работает как сейчас:** без окна, с полем Title.

## Термины

- **Ввод** — один файл, ссылка или вставленный текст: то, что сейчас добавляется за раз (`SourceInput`). Видео с приложенным `.srt` — один ввод.
- **Пачка** — несколько вводов, добавленных одним действием.
- **Заготовка** (`SourceDraft`) — будущий источник: всё, из чего `SourceWriter` его создаст, кроме названия и коллекции. Из одного ввода получается одна заготовка, из epub с ответом «по главам» — по одной на главу.
- **Своё название** заготовки — ровно то, что источник получил бы при одиночном добавлении (`content.title` от читателя, как сейчас: метаданные или заголовок, иначе имя файла); у главы epub — заголовок главы, иначе `Chapter N`. Читатели не меняются.
- **Подпись** заготовки — откуда она взялась, для левой колонки окна: имя файла с расширением; у главы epub — `chapter N`.
- **Правило названий** (`NamingRule`) — строка с переменными `{n}` (номер по порядку, с 1) и `{title}` (своё название). Пример: `Atomic Habits ch{n}`.
- **Окно названий** — шаг добавления, когда заготовок две и больше.

## Окно названий

Макет согласован с Максом:

```
Add 10 files                              (у epub: Add «Deep Work»)

Collection   [ Atomic Habits          ▾ ]
Name them    [ Atomic Habits ch{n}        ]
             {n} — number in order, {title} — the file's own title

File                                  →  Source
Atomic_Habits_FINAL(2)_01_scan.txt    →  Atomic Habits ch1
ah-02 v2.txt                          →  Atomic Habits ch2
chapter three (copy).md               →  Atomic Habits ch3
…
                                         Cancel   [Add]
```

- **Collection** — выбор из существующих коллекций (с путём, если коллекция вложенная), создание новой по введённому имени или «No collection». Новая коллекция создаётся на верхнем уровне в конце, как сейчас у epub.
  - У epub по умолчанию стоит коллекция с именем книги: существующая на верхнем уровне или новая (как сейчас `BookHandler._collection_id`).
  - У пачки по умолчанию «No collection».
- **Name them** — правило названий. По умолчанию — правило из настроек. При вводе правые названия пересчитываются сразу.
- **Строку справа можно переписать руками.** Переписанная строка дальше не следует правилу.
- **Порядок строк** — порядок, в котором источники встанут в списке и получат `{n}`:
  - пачка — по подписи, регистр не важен, числа по значению (`ch2` раньше `ch10`), как `_name_key` в `source_order.py`;
  - главы epub — порядок книги.
- Все источники группы создаются с одним `created_at`, чтобы в списке «по дате» они шли в порядке окна (как сейчас у глав).

## Ввод нескольких файлов

- **Перетаскивание** нескольких файлов в macOS-приложении. Исключение, как сейчас: одно видео и один `.srt` — это одно видео с субтитрами, а не пачка.
- **Choose file…** — выбор нескольких файлов (`NSOpenPanel.allowsMultipleSelection = true`).
- В поле ввода пачка — это пути, каждый на своей строке. Поле можно править руками: удалить строку, вставить ещё путь.
- Перетаскивание и пикер **заменяют** содержимое поля, как сейчас (моё решение: сохраняю текущее поведение).
- **Что в поле — пачка, решает backend** (`typed_input` / `DescribeInputUseCase`): строк две и больше, и каждая непустая строка выглядит как путь к файлу по тем же правилам, по которым сейчас одна строка считается путём. Если какого-то файла нет — проблема ввода `FILE_NOT_FOUND`, как у одиночного пути, с именем файла в сообщении; текстом такое поле не считается. Подпись режима: `10 files`.
- Поля Title и Subtitles для пачки не показываются: названия задаются в окне.
- **Видео и `.srt` в пачке.** Пара «видео + srt» склеивается только в одиночном случае (одно видео + один `.srt`, как сейчас). В пачке каждый файл — свой ввод: `.srt` становится источником-субтитрами, видео — видео со своими вопросами. Склейки по именам нет.

## Модель

**Домен:**
- `NamingRule` (value object) вместо `ChapterTitleTemplate`: `pattern`, `render(number: int, own_title: str) -> str`. Проверка как сейчас: правило без `{n}` и `{title}` дало бы всем одно название — `ValueError`.
- `CollectionChoice` (value object): ровно одно из `existing_id: int`, `new_name: str`; пустой выбор — «No collection».

**Application:**
- `SourceDraft` (dataclass, `source_intake`): `document`, `kind`, `source_format`, `video`, `own_title`, `label`, `words`.
- `KindHandler.create(...) -> SourcesCreated` заменяется на `drafts(content, answers, source_format) -> tuple[SourceDraft, ...]`. Обработчики больше не пишут в базу и не создают коллекции.
  - `SingleSourceHandler` — одна заготовка.
  - `BookHandler` — заготовка на главу или одна на всю книгу по ответу `book.split`. Вопрос `book.split` остаётся, но без `details`: список глав теперь показывает окно названий.
- `SourceGroupWriter` (новый, `source_intake`) — пишет заготовки: создаёт коллекцию по `CollectionChoice`, ставит названия, общий `created_at`, вызывает `SourceWriter.write`. Всё в одной транзакции: если хоть один источник не создался, не создаётся ни один.
- `AddSourceUseCase.execute(inputs, title, answers, naming)`:
  1. Для каждого ввода — читатель и обработчик, как сейчас. Неотвеченные вопросы всех вводов возвращаются вместе (`QuestionsRequired`), у каждого вопроса — индекс ввода и его подпись.
  2. Заготовки всех вводов собираются в одну группу. Пачка сортируется по подписи; главы epub внутри пачки идут подряд в порядке книги, на месте своего файла.
  3. Одна заготовка → создаётся как сейчас: название из `title`, иначе своё; без коллекции.
  4. Две и больше без `naming` → `NamingRequired`. Поле Title у одиночного epub работает как сейчас — заменяет имя книги до обработчика (`_titled`), поэтому попадает в заголовок окна и в коллекцию по умолчанию.
  5. Две и больше с `naming` → `SourceGroupWriter`.
- `RenderNamesUseCase.execute(rule, own_titles) -> list[str]` — пересчёт правых названий при вводе правила. Файлы не перечитываются: окно присылает свои названия из `NamingRequired`.

**DTO:**
- `AddSourceRequest`: `text`, `subtitles_path`, `title` — как сейчас; `answers: list[dict[str, str]]` — по одному словарю на ввод (у двух epub в пачке одинаковый id вопроса `book.split`); `naming: NamingDTO | None`.
- `NamingDTO`: `collection: CollectionChoiceDTO | None`, `rule: str`, `titles: dict[int, str]` — переписанные руками строки по номеру строки.
- `QuestionDTO`: + `input_index: int`, `input_label: str | None` (подпись нужна, только когда вводов несколько).
- `NamingRequired`: `heading` (`Add 10 files` / `Add «Deep Work»`), `items: list[{label, own_title, words}]` в порядке окна, `default_collection: CollectionChoiceDTO | None`, `default_rule: str`.
- `RenderNamesRequest`: `rule`, `own_titles: list[str]` → `list[str]`. Ошибка правила — 422 с текстом для поля.

**API:**
- `POST /sources/add` — тот же эндпоинт, ответ: `QuestionsRequired | NamingRequired | SourcesCreated`.
- `POST /sources/render-names` — новый.
- Список коллекций для выбора — существующий `GET /collections`.

**Frontend:**
- `AddSourceForm`: перетаскивание и пикер нескольких файлов кладут пути в поле, каждый на своей строке; `withDroppedPaths` сохраняет правило «видео + srt».
- `nativeHost.pickFiles` — рядом с `pickFile`, возвращает список путей. `pickFile` остаётся для `PathField` (выбор одного `.srt`).
- `QuestionsModal`: у вопросов с `input_label` подпись файла над вопросом.
- `NamingModal` (новый) — окно названий. Правые названия приходят из `render-names` (с задержкой, как `describeInput`); переписанные строки фронт хранит как локальный UI-state и отправляет в `naming.titles`.

**macOS:** `FilePickerBridge` — параметр множественного выбора, при нём ответ — массив путей.

## Настройка правила по умолчанию

Настройка `book_chapter_title_template` (Settings) становится `naming_rule` — правилом по умолчанию в окне названий для любой группы, не только epub. Переменные `{{n}}` → `{n}`, `{{chapter_title}}` → `{title}`. Сохранённое значение переносит Alembic-миграция данных.

`{{book_name}}` в новом правиле нет: название коллекции в правило не подставляется, оно пишется в правило текстом. **Открытый вопрос для Макса:** что делать с сохранённым правилом, где есть `{{book_name}}` (в том числе текущим умолчанием `{{book_name}} ch{{n}}`):
1. сбросить в новое умолчание `{title}`;
2. при открытии окна для epub подставлять имя книги текстом в правило по умолчанию (`Deep Work ch{n}`), то есть `{book}` остаётся переменной только для умолчания.

## Сохраняемое поведение

- Одиночное добавление файла, ссылки, текста, темы, фразы — без изменений, с полем Title.
- epub: вопрос «по главам / одной книгой», коллекция с именем книги по умолчанию, повторное добавление книги — в ту же коллекцию верхнего уровня, порядок глав в списке.
- Видео + `.srt` перетаскиванием — одно видео с субтитрами.
- Вопросы читателей (дорожки видео, текст или песня) задаются для каждого ввода пачки.

## Этапы

1. Домен и application: `NamingRule`, `CollectionChoice`, `SourceDraft`, `drafts` вместо `create`, `SourceGroupWriter`, `AddSourceUseCase` со списком вводов, `RenderNamesUseCase`, миграция настройки. Одиночные добавления и epub проходят через новый путь; тесты.
2. API и DTO.
3. Frontend: пачка в поле, `NamingModal`, подписи в `QuestionsModal`; macOS-пикер.
