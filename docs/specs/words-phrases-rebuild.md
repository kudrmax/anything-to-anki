# Слово и фразы, обновление без потерь, Learn → Known через Anki

Решения согласованы с Максом 14–15.10.2026. Это основа, нужная при любом будущем интерфейсе больших источников; части источника и выбор объёма работы — отдельная задача (черновик: `source-parts.md`, отложен).

## Цель

1. **Слово и фразы.** Слово встречается в тексте много раз — у каждого вхождения своя фраза со своей генерацией. Фраза слова выбирается среди всех вхождений, а не первых десяти; человек может выбрать другую фразу, не теряя уже сгенерированного.
2. **Обновление без потерь.** Поменялась логика отбора, фраз или уровень — источник пересобирается, решения Learn/Known/Skip и сгенерированное не теряются. Нынешняя переобработка, стирающая решения, уходит.
3. **Learn → Known по Anki.** Слово становится знакомым, когда его карточка в Anki реально выучена, а не в момент экспорта.

## Термины

- **Слово** (`StoredCandidate`, таблица `candidates` — как сейчас, одно на лемму+POS в источнике): решение, фраза решения, CEFR, частотность, usage, число вхождений, произношение, картинка. Экспорт, Anki-синхронизация, жалобы — по слову, как сейчас.
- **Фраза** (`Phrase`, таблица `phrases`) — вхождение слова в тексте: место цели (`target_start`, `target_end` в координатах документа — стабильный ключ вхождения), текст фразы, её слова, оценка фрагмента, и всё, что сгенерировано **для фразы**: Polish, определение, озвучка фразы, видеоклип, cloze, ручная граница.
- **Показанная фраза** — та, с которой слово показывается и экспортируется: фраза решения, иначе выбранная человеком, иначе лучшая по оценке (при равенстве — раньше по тексту). Отбор — одна заменяемая функция `select_phrase`.
- **Тронутая фраза** — показанная, или фраза решения, или с любым результатом генерации, или с ручной правкой (граница, ручное добавление, пример как фраза), или с поставленной задачей генерации. Одно доменное определение (`is_touched`); SQL-фильтр строится из него и проверяется тем же тестом.
- **Зрелая карточка** — в Anki интервал повторения ≥ порога (настройка `anki_mature_interval_days`, по умолчанию 21 — стандартный порог «mature» в Anki).

## Как пользуется

### Другие фразы

На карточке — «Other phrases (N)», если у слова больше одной фразы: список вхождений (фраза, пометка, если у неё уже есть Polish/определение). Выбор делает эту фразу показанной. Прежняя фраза со своими результатами остаётся в базе; вернулся к ней — всё на месте. После решения слова фраза решения фиксирована, список доступен только для просмотра.

Меню ✨ работает по показанным фразам, как сейчас по карточкам.

### Обновить

Вместо «Reprocess» в меню строки источника — «Rebuild…»:

- пересобирает нетронутые фразы по текущей логике, уровню и знаниям; появляются новые слова, ушедшие — исчезают, если у них нет решения и тронутых фраз;
- галочка «Also unreviewed cards» — пересобираются и показанные фразы слов без решения: у фразы с новым текстом результаты генерации сбрасываются; ручные фразы не трогаются;
- до подтверждения видно, сколько слов появится, уйдёт и сколько показанных фраз изменится;
- подпись: «A new AI prompt is applied through ✨ → Regenerate».

Решения не теряются никогда; модалка «decisions will be lost» уходит. Источник в ERROR без карточек — «Rebuild» обрабатывает его заново.

### Learn → Known

- Экспорт в Anki больше **не** добавляет слово в Known.
- При **каждом экспорте** приложение спрашивает у AnkiConnect интервалы карточек уже экспортированных слов; слова со зрелой карточкой добавляются в Known (как сейчас Known добавляется — через `UserVocabulary.mark_known`, Unknown побеждает).
- Anki недоступен — проверка пропускается, экспорт идёт как обычно; в лог — предупреждение.
- Настройка «Mature after (days)» рядом с настройками Anki.
- Уже добавленные в Known экспортом слова остаются Known (без миграции).

## Модель

### Таблицы

| Таблица | Что | Изменение |
|---|---|---|
| `phrases` | `id`, `candidate_id` (CASCADE), `target_start`, `target_end`, `source_phrase`, `phrase_position`, `polished_phrase`, `polish_reverted`, `fragment_score`, `edited_by_user`, `created_at` | новая; уникальность `(candidate_id, target_start)` для фраз с местом |
| `candidates` | слово | `+ shown_phrase_id` (выбор человека, SET NULL), `+ decided_phrase_id` (SET NULL); фразовые колонки (`source_phrase`, `polished_phrase`, `polish_reverted`, `phrase_position`) переезжают в `phrases` |
| `candidate_meanings`, `candidate_media`, `candidate_tts`, `candidate_clozes` | результаты фразы | ключ `candidate_id` → `phrase_id` |
| `candidate_pronunciations`, `candidate_meaning_images` | результаты слова | без изменений |
| `card_reports` | жалобы | + `phrase_id` (фраза, на которую жалоба) |
| `document_parses` | кэш spaCy: PK `(document_hash, analyzer_version)`, токены zlib-BLOB; записи без живого документа удаляются | новая |
| `source_operations` | `source_id` PK, `kind`, `started_at` — одна длинная операция на источник (обработка, обновление); вторая получает 409; блокировка не через статус источника | новая |

### Домен

- `Phrase` (entity); `StoredCandidate` — слово с `shown_phrase_id`, `decided_phrase_id`; свойство «показанная фраза» вычисляет `select_phrase`.
- `select_phrase(word, phrases) -> Phrase` (domain service).
- `is_touched(phrase, word, has_job)` (domain spec).
- `plan_rebuild(existing, built, include_open) -> RebuildPlan` (domain service): чистый расчёт — какие фразы создать, удалить, изменить, какие слова создать/удалить; превью = счётчики плана, выполнение = применение плана.
- `MaturityThreshold` (VO) и порт `AnkiConnector.card_intervals(note_ids) -> dict[int, int]`.

## Поведение

### Анализ

`AnalyzeText` отдаёт **каждое** вхождение с фразой и её оценкой (`MAX_OCCURRENCES_COMPARED` и выбор лучшего уходят из анализатора). Выбор фразы в пределах предложения (исправление от 14.10.2026) делает это быстрым: книга 168 тыс. слов — 38 с, из них spaCy 30 с; ~4 тыс. слов, ~12,8 тыс. фраз. Разбор spaCy кэшируется по хешу документа и версии анализатора — повторный анализ ~8 с.

### Обработка источника

Как сейчас, но результат — слова и все их фразы; показанная — лучшая.

### Пересборка — `RebuildSource(source_id, include_open)` + `PreviewRebuild`

1. Анализ (вне транзакции).
2. `plan_rebuild`: вхождение узнаётся по `target_start/target_end`; нетронутые фразы удаляются и создаются заново, тронутые остаются без дублей; слово без фраз и без решения удаляется; новые слова создаются; данные слова (CEFR, частотность, usage, число вхождений) обновляются.
3. `include_open`: показанные фразы слов без решения сверяются по ключу вхождения: текст тот же — без изменений; другой — новый текст, позиция, слова, оценка, результаты генерации фразы сбрасываются; вхождения нет — фраза удаляется, показанной становится лучшая из оставшихся. Ручные фразы пропускаются. Отказ при активных заданиях генерации источника.
4. Применение плана — одна короткая транзакция. Захват `source_operations` атомарный.

`ReprocessSource`, `GetReprocessStats`, `ReprocessModal`, кэш обогащения (`enrichment_cache`) удаляются.

### Другая фраза — `ChoosePhrase(phrase_id)`

`shown_phrase_id` = эта фраза. У слова с решением — отказ.

### Решение — `MarkCandidate` (как сейчас) + фраза

Решение пишет `decided_phrase_id` = показанная фраза. Экспорт берёт фразу решения.

### Генерация

`GenerationTarget` работает по показанной фразе слова; результаты фразы пишутся по `phrase_id`, слова — по `candidate_id`. Постановка задачи делает фразу тронутой в той же транзакции.

### Экспорт и зрелость

`SyncToAnki`: `_mark_exported` больше не вызывает `mark_known`. В начале каждого экспорта — `RefreshKnownFromAnki`: note id экспортированных слов (`anki_synced_cards`) → `AnkiConnector.card_intervals` → слова со зрелой карточкой → `UserVocabulary.mark_known`. Недоступен Anki — пропуск с предупреждением в логе.

### Производительность

Список источников и прогресс считаются лёгкими SQL-проекциями, без загрузки всех фраз; клик Known не перечитывает все источники полностью. Бюджет времени — в интеграционном тесте на книге.
