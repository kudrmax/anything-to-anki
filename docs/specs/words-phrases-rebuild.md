# Слово и фразы, обновление без потерь, Learn → Known через Anki

Решения согласованы с Максом 14–15.10.2026. Это основа, нужная при любом будущем интерфейсе больших источников; части источника и выбор объёма работы — отдельная задача (черновик: `source-parts.md`, отложен).

## Цель

1. **Слово и фразы.** Слово встречается в тексте много раз — у каждого вхождения своя фраза со своей генерацией. Фраза слова выбирается алгоритмом среди всех вхождений, а не первых десяти; когда алгоритм меняет фразу, сгенерированное для прежней не теряется. Ручного выбора фразы нет (решение Макса 15.10.2026).
2. **Обновление без потерь.** Поменялась логика отбора, фраз или уровень — источник пересобирается, решения Learn/Known/Skip и сгенерированное не теряются. Нынешняя переобработка, стирающая решения, уходит.
3. **Learn → Known по Anki.** Слово становится знакомым, когда его карточка в Anki реально выучена, а не в момент экспорта. Пока учится — состояние «учу»: не предлагается новым, но во фразах других слов считается незнакомым.

## Термины

- **Слово** (`StoredCandidate`, таблица `candidates` — как сейчас, одно на лемму+POS в источнике): решение, фраза решения, CEFR, частотность, usage, число вхождений, произношение, картинка. Экспорт, Anki-синхронизация, жалобы — по слову, как сейчас.
- **Фраза** (`Phrase`, таблица `phrases`) — вхождение слова в тексте: место цели (`target_start`, `target_end` в координатах документа — стабильный ключ вхождения), текст фразы, её слова, оценка фрагмента, и всё, что сгенерировано **для фразы**: Polish, определение, озвучка фразы, видеоклип, cloze, ручная граница.
- **Фраза слова** (`candidates.phrase_id`, NOT NULL для слов с текстом) — с ней слово показывается, генерируется и экспортируется. Правило: **фраза слова = лучшая по текущему алгоритму (`select_phrase`), пересчитывается при каждой обработке и каждом Rebuild**, кроме двух случаев: (1) у слова есть решение; (2) на текущей фразе есть сгенерированное, а Rebuild запущен без галочки «Also unreviewed cards». Если алгоритм снова выбирает фразу, где уже есть сгенерированное, — оно используется, повторной генерации нет. Значение хранится в колонке (не вычисляется при чтении), чтобы чтение было простым JOIN.
- **Тронутая фраза** — фраза слова, или с любым результатом генерации или задачей, или с ручной правкой (граница, ручное добавление, пример как фраза). Определение одно, в домене (`is_touched`), считается по лёгкой проекции фраз; SQL-дубля нет.
- **Учу** (`Learning`) — у слова есть Learn в любом источнике или оно экспортировано, а карточка ещё не зрелая. Такие леммы не становятся новыми кандидатами в других источниках; во фразах других слов считаются незнакомыми (фраза уходит в Extra). Источник истины — `UserVocabulary`.
- **Зрелая заметка** — у всех её не приостановленных карточек в Anki интервал ≥ порога (настройка `anki_mature_interval_days`, по умолчанию 21 — стандартный порог «mature»); отрицательный интервал (обучение) — не зрелая; удалённая заметка пропускается.

## Как пользуется

Меню ✨ работает по фразам слов, как сейчас по карточкам.

### Обновить

Вместо «Reprocess» в меню строки источника — «Rebuild…»:

- пересобирает нетронутые фразы по текущей логике, уровню и знаниям; появляются новые слова, ушедшие — исчезают, если у них нет решения и тронутых фраз;
- галочка «Also unreviewed cards» — пересобираются и фразы слов без решения: у фразы с новым текстом результаты генерации сбрасываются; ручные фразы не трогаются;
- до подтверждения видно, сколько слов появится, уйдёт и сколько фраз слов изменится и у скольких из них пропадёт сгенерированное;
- подпись: «A new AI prompt is applied through ✨ → Regenerate».

Решения не теряются никогда; модалка «decisions will be lost» уходит. Источник в ERROR без карточек — «Rebuild» обрабатывает его заново.

### Learn → Known

- Экспорт в Anki больше **не** добавляет слово в Known.
- При **каждом экспорте**, в том числе когда новых карточек нет, приложение спрашивает у AnkiConnect интервалы карточек уже экспортированных слов; слова со зрелой заметкой становятся Known через `UserVocabulary.mark_mature`: лемму из Unknown не трогает, слово, удалённое человеком из Known, не возвращает (каждая заметка повышается один раз: `anki_synced_cards.matured_at`). После — пересчёт разделов источников с этими леммами.
- Результат виден: в итоге экспорта «5 words learned in Anki → Known», в списке Known пометка «from Anki».
- Anki недоступен — экспорт, как и сейчас, сообщает об этом; проверки зрелости нет.
- Настройка «Mature after (days)» рядом с настройками Anki.
- Уже добавленные в Known экспортом слова остаются Known (без миграции).

## Модель

### Таблицы

| Таблица | Что | Изменение |
|---|---|---|
| `phrases` | `id` (sqlite_autoincrement), `candidate_id` (CASCADE), ключ вхождения — структурная позиция начала цели (`block`, `line`, `char`), `source_phrase`, `phrase_position`, `polished_phrase`, `polish_reverted`, `fragment_score`, `edited_by_user`, `created_at` | новая; уникальность ключа вхождения у фраз с местом |
| `candidates` | слово | `+ phrase_id`; фразовые колонки (`source_phrase`, `polished_phrase`, `polish_reverted`, `phrase_position`) переезжают в `phrases` |
| `jobs` | задачи генерации | `+ phrase_id` (CASCADE): результат пишется в свою фразу |
| `anki_synced_cards` | экспорт | `+ matured_at` |
| `candidate_meanings`, `candidate_media`, `candidate_tts`, `candidate_clozes` | результаты фразы | ключ `candidate_id` → `phrase_id` |
| `candidate_pronunciations`, `candidate_meaning_images` | результаты слова | `ipa` переезжает из `candidate_meanings` в произношение (свойство слова); картинка остаётся на слове |
| `card_reports` | жалобы | + `phrase_id` (фраза, на которую жалоба) |
| `document_parses` | (можно отдельной итерацией) кэш spaCy через адаптер-декоратор `CachingDocumentAnalyzer`; версия — spaCy+модель+константа постобработки; PK `(document_hash, analyzer_version)`, токены zlib-BLOB; записи без живого документа удаляются | новая |
| `source_operations` | `source_id` PK, `kind`, `started_at` — одна длинная операция на источник (обработка, обновление); вторая получает 409; очищается при старте приложения; `PROCESSING` уходит из статуса источника | новая |

### Домен

- `Phrase` (entity); `StoredCandidate` — слово с `phrase_id`.
- `select_phrase(word, phrases) -> Phrase` (domain service).
- `is_touched(phrase, word, has_job)` (domain spec).
- `plan_rebuild(existing, built, include_open) -> RebuildPlan` (domain service): чистый расчёт — какие фразы создать, удалить, изменить, какие слова создать/удалить; превью = счётчики плана, выполнение = применение плана.
- `MaturityThreshold` (VO, `is_mature(intervals)`) и порт `AnkiConnector.card_intervals(note_ids) -> dict[int, tuple[int, ...]]` (пачками; `findCards nid:` + `cardsInfo`).
- Данные слова (CEFR, частотность, usage) не зависят от выбранной фразы: считаются по лемме, а не по лучшему вхождению. Слово = лемма (+ POS для обычных слов, `PHRASAL_VERB_POS` для фразовых глаголов), как группирует анализатор.

## Поведение

### Анализ

`AnalyzeText` отдаёт **каждое** вхождение с фразой и её оценкой (`MAX_OCCURRENCES_COMPARED` и выбор лучшего уходят из анализатора). Выбор фразы в пределах предложения (исправление от 14.10.2026) делает это быстрым: книга 168 тыс. слов — 38 с, из них spaCy 30 с; ~4 тыс. слов, ~12,8 тыс. фраз. Разбор spaCy кэшируется по хешу документа и версии анализатора — повторный анализ ~8 с.

### Обработка источника

Как сейчас, но результат — слова и все их фразы; фраза слова — лучшая по `select_phrase`.

### Пересборка — `RebuildSource(source_id, include_open)` + `PreviewRebuild`

1. Анализ (вне транзакции). Темы и Saved phrases не пересобираются.
2. `plan_rebuild`: вхождение узнаётся по ключу (структурная позиция начала цели); нетронутые фразы удаляются и создаются заново, тронутые остаются без дублей; новые слова создаются; слово без фраз и без решения удаляется; данные слова (CEFR, частотность, usage, число вхождений) обновляются.
3. Тронутые фразы при `include_open` (у слов без решения, кроме ручных): тот же текст — без изменений; другой текст того же вхождения — новый текст, позиция, слова, оценка, результаты генерации этой фразы сбрасываются; вхождения больше нет — фраза удаляется.
4. Фраза слова пересчитывается по правилу из «Терминов»: `select_phrase` по всем фразам слова, кроме слов с решением и (без `include_open`) слов, у текущей фразы которых есть сгенерированное.
5. Загрузка фраз, `plan_rebuild` и применение — в одной write-транзакции после анализа (иначе действия человека за время анализа терялись бы). Задачи генерации затронутых фраз отменяются точечно, общего отказа нет. Захват `source_operations` атомарный.
6. Идемпотентность: Rebuild дважды без изменений даёт пустой план (тест).

`ReprocessSource`, `GetReprocessStats`, `ReprocessModal`, кэш обогащения (`enrichment_cache`) удаляются.

### Решение — `MarkCandidate` (как сейчас) + фраза

Решение фиксирует фразу слова. Экспорт берёт фразу слова.

### Генерация

`GenerationTarget` работает по фразе слова; задача несёт `phrase_id`, результат пишется в эту фразу (фраза удалена — задача тихо завершается). Медиафайлы фраз — `p{phrase_id}_…`; reconciler при старте знает этот формат.

### Экспорт и зрелость

`SyncToAnki`: `_mark_exported` больше не вызывает `mark_known` (слово становится «учу»). В начале каждого экспорта, до раннего выхода «нечего экспортировать», — `RefreshKnownFromAnki` (см. выше).

### Производительность

Список источников и прогресс считаются лёгкими SQL-проекциями по фразе слова (JOIN по `phrase_id`), без загрузки всех фраз; пересчёт разделов после изменения знаний — только по источникам, где встречается эта лемма. Бюджет времени — в интеграционном тесте на книге.

## Миграция 0049

- Бэкап `app.db` перед upgrade (в `make up`).
- `phrases`: по одной фразе на существующую карточку из её фразовых колонок; ключ вхождения — из позиции фразы и цели (логика заморожена копией в миграции); `candidates.phrase_id` = эта фраза.
- Результаты фразы и активные `jobs` перевязываются на `phrase_id`; `card_reports.phrase_id` — фраза карточки; медиафайлы переименовываются в `p{phrase_id}_…`; `ipa` — в произношение.
- Состояние «учу» для уже экспортированных слов не нужно: экспорт до сих пор делал их Known.
- Фразовые колонки `candidates` и таблица `enrichment_cache` удаляются.
- Alembic `env.py` без `PRAGMA foreign_keys` — batch-alter не каскадит; assert в миграции.
- Перед созданием проверить номер и `down_revision` на всех ветках (на ветках два разных `0048_*`).
- Тест миграции на копии prod-базы: фраз столько же, сколько карточек, результаты и задачи перевязаны.
