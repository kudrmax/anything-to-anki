# Части источника, карточки в работе и обновление без потерь

Продуктовые решения согласованы с Максом 14.10.2026, история обсуждения — в документе «Большие источники — проблема».

## Цель

Большой источник (книга, сериал, огромная статья) не генерируется целиком и не замораживается на момент загрузки.

- Человек выбирает **кусок** источника (фильтр «Где») и **объём** работы («Взять ещё N», отметка «В работе») независимо.
- Карточки, во что человек ещё ничего не вложил, всегда можно пересобрать по текущей логике и знаниям, не трогая остальное.
- Фраза для слова берётся из выбранного куска: готовишься к главе 3 — фразы из главы 3.

## Термины

- **Источник** — то, что человек изучает как целое: книга, сериал, статья, песня.
- **Часть** — кусок содержимого источника со своим документом и, возможно, своим видео: глава EPUB, раздел статьи, серия, дописанный кусок. У источника хотя бы одна часть.
- **Страница** — только подпись диапазона в фильтре «Где»: кусок части фиксированного размера `WORDS_PER_PAGE` (250 слов документа), переводится в диапазон позиций. Нигде не хранится.
- **Карточка** (`StoredCandidate`) — одно **вхождение** слова в тексте с фразой вокруг него. Слово, встретившееся в тексте 5 раз, — 5 карточек. Все карточки одного вида: генерация, решение, отметка «в работе» — как у любой карточки.
- **Показанная карточка слова** — в выборке фильтра у слова видна одна карточка: та, что в работе, иначе с лучшей оценкой фразы (оценка фрагмента, которой приложение уже выбирает фразу), при равенстве — раньше по тексту. Остальные карточки слова скрыты.
- **В работе** (`in_work`) — отметка на карточке: «работаю над ней сейчас». Ограничивает показ и генерацию; больше ни на что не влияет.
- **Решение** — LEARN / KNOWN / SKIP. Принимается по слову: ставится на все карточки слова в источнике.
- **Нетронутая карточка** — без решения, без результатов генерации и не в работе. Только такие приложение пересобирает само.

## Почему карточка на вхождение

Сейчас на слово в источнике одна карточка с лучшей фразой среди первых десяти вхождений. Это баг: при «Где: гл. 3» слово из главы 3 пропадает или показывает фразу из другой главы; выбор смещён к началу текста. Карточка на вхождение убирает это без особых случаев: выборка — обычный `WHERE` по части и позиции, затем одна показанная карточка на слово.

Объём: строка на вхождение слова выше уровня, на книгу — десятки тысяч строк. Генерация и «в работе» касаются только показанных карточек, скрытые ничего не стоят. Индексы `(source_id, lemma)`, `(part_id, block)`.

## Модель

### Таблицы

| Таблица | Что | Изменение |
|---|---|---|
| `sources` | название, коллекция, `kind`, `role`, статус, `topic_query` | уходят `format`, `source_url`, `video_path`, `audio_track_index` |
| `source_parts` | `id`, `source_id` (CASCADE), `position`, `title`, `format`, `source_url`, `video_path`, `audio_track_index`, `created_at` | новая |
| `part_documents` | `part_id` (PK, CASCADE), `document` JSON | вместо `source_documents` |
| `candidates` | карточки | `+ part_id` (CASCADE), `+ in_work`, `+ fragment_score`; позиция фразы — внутри документа части |

### Домен

- `SourcePart` (entity): `has_video`, `can_polish_phrases` переезжают сюда с `Source`. `Source.has_video` — есть часть с видео (для списка).
- `Where` (value object): `parts: frozenset[int] | None` (None — все), `pages: PageSpan | None`; диапазон страниц только при одной выбранной части, иначе `ValueError`.
- `CardFilter` (value object): `where`, `in_work_only: bool`, `sections: frozenset[CandidateSection]`.
- `document_pages` (domain service): `page_count(document)`, `range_of(document, pages)`, `time_span(document, pages)` для подписи видео временем.
- `shown_cards` (domain service): из карточек выборки — одна на слово по правилу показанной карточки.
- `expected_section` (domain service): раздел, ожидаемый у готовой карточки — для «Взять ещё».
- `StoredCandidate.is_untouched`.

## Поведение

### Загрузка

- `FormatReader` → `KindHandler` → `SourceWriter` создаёт источник и части:
  - EPUB — часть на главу (`infrastructure/epub/chapters.py`); вопрос `book.split` и источник на главу удаляются;
  - Markdown/HTML — часть на раздел верхнего уровня, если заголовки есть; иначе одна часть;
  - видео / SRT / YouTube / текст / песня — одна часть.
- Обработка: `RebuildCards`, затем `TakeCards` на `cards_per_take` по сортировке по умолчанию.

### Пересборка — `RebuildCards(source_id, include_open)`

1. Анализ каждой части (`AnalyzeText` по текущему уровню, словарю, частотности): для **каждого** вхождения слова — фраза вокруг него и её оценка. `MAX_OCCURRENCES_COMPARED` и выбор лучшего вхождения уходят из анализатора.
2. Нетронутые карточки источника удаляются, на их место — карточки из анализа. Вхождения слов с решением в источнике не создаются.
3. `include_open`: карточки в работе без решения сверяются с анализом по (лемма, POS, часть, позиция цели):
   - фраза та же — без изменений;
   - фраза другая — новые фраза, позиция, слова, оценка; результаты генерации, зависящие от фразы (polish, meaning, TTS, media), удаляются — генерация подхватит их как недостающие;
   - вхождения нет (слово больше не подходит) — карточка удаляется.
   Отказ, если у источника есть активные задания генерации.
4. Карточки с решением или с генерацией вне `include_open` не трогаются никогда.

Время пересборки большой книги замерить до реализации (этап 0); если долго — кэшировать разбор spaCy части: он не зависит от знаний и уровня.

### Взять ещё — `TakeCards(source_id, filter, sort, count)`

1. `RebuildCards(include_open=False)`.
2. Карточки в `filter.where`, слова без карточки в работе и без решения → `shown_cards` → упорядочить по `expected_section`, затем `CandidateSorter` → первые `count` получают `in_work`.

`expected_section`: раздел — свойство готовой карточки, а готовая фраза — фраза после Polish.
- часть с Polish (`can_polish_phrases`): PROBABLY_KNOWN для мусора и частых слов, иначе READY — сложность исходной фразы снимает Polish;
- часть без Polish (видео): раздел исходной фразы.

Фильтр «Раздел» к взятию не применяется. Polish наперёд и Polish всего источника отвергнуты (14.10.2026): заранее пришлось бы полировать каждое вхождение, а пересборка выбрасывала бы работу.

Генерации нет. `count` по умолчанию — настройка `cards_per_take` (100).

### Выбор фразы из текста — `TakeOccurrence(candidate_id)`

Клик по подсвеченному вхождению в правой панели: эта карточка получает `in_work`; другая карточка того же слова в работе, если нетронута кроме отметки, отметку теряет. Так человек выбирает фразу сам; раскрывать скрытые карточки в списке не нужно.

### Обновление — `UpdateSource(source_id, scope)`

- `REMAINING` → `RebuildCards(include_open=False)`.
- `REMAINING_AND_OPEN` → `RebuildCards(include_open=True)`.

`ReprocessSource`, `GetReprocessStats`, `ReprocessModal`, кэш обогащения (`enrichment_cache`) удаляются: решения не теряются, сгенерированное остаётся на неизменённых карточках.

### Дописать часть — `AddPart(source_id, input, title?)`

То же чтение входа, что у загрузки; часть в конец (`position = max + 1`), название по умолчанию «Part N». Затем `RebuildCards(include_open=False)`. В работу ничего не берётся.

### Решение

`DecideCard(candidate_id, status)` ставит статус на все карточки слова (лемма, POS) в источнике. Показанной становится эта карточка.

### Фильтры, чтение, генерация

- `GetSource(source_id, sort, filter)`: карточки в `where` (+ `in_work_only`) → `shown_cards` → раздел (живой, как сейчас) → `filter.sections` (во всех сортировках) → сортировка. Разделы в списке — как в `candidate-sections.md`.
- `GetSourceDocument(part_id)`: документ части, подсветка — карточки, проходящие фильтр.
- `GetGenerationStatus` / `RunGeneration(source_id, kind, scope, sort, filter)`: по показанным карточкам, проходящим `filter`. Выключен «В работе» — генерируются все показанные карточки куска.
- Прогресс: внутри источника — по Ready среди показанных карточек в работе; источник «разобран», когда у каждого слова источника, чья показанная карточка Ready, есть решение.

### Генерация и видео

- `GenerationTarget.applies_to` и `blocker` принимают часть карточки, не источник.
- Медиа: `video_path`, формат и дорожка — с части карточки; файлы — `media_root/<source_id>/<candidate_id>_*`.
- Скачивание YouTube и очистка — на уровне части.

## API (кратко)

- `GET /sources/{id}?sort=&parts=&pages=&in_work_only=&sections=` — деталь + `parts: [{id, title, position, page_count, has_video}]`.
- `POST /sources/{id}/take` `{count, filter, sort}`; `POST /candidates/{id}/take`.
- `POST /sources/{id}/update` `{scope}`.
- `POST /sources/{id}/parts` — дописать часть.
- `GET /sources/{id}/generation`, `POST .../generation/{kind}` — принимают фильтр.
- Удаляются `/reprocess`, `/reprocess-stats`.

## Frontend

- Шапка ревью: меню фильтра (секции «Где» / «В работе» / «Раздел»), ↻ «Обновить» рядом с ✨ (тот же двухуровневый `Menu`; тексты временные: Remaining words / Remaining words and open cards).
- Внизу списка — «Take N more · ~M left».
- `SourceRow`: Reprocess → «Update» с теми же двумя пунктами; без модалки.
- «Add part» — открывает форму добавления (место кнопки решим при реализации).
- Клик по вхождению в правой панели — `TakeOccurrence`.
- Настройка `cards_per_take` в Settings рядом с `images_per_source`.
- Фронт ничего не вычисляет: страницы, показанные карточки, разделы, «осталось» приходят с backend.

## Миграция 0049

- `source_parts`: часть на источник (`position=0`, `title` — название источника, формат и видео — из `sources`).
- `part_documents` из `source_documents`.
- `candidates.part_id` — единственная часть источника; `in_work = 1` для всех существующих карточек; `fragment_score` — NULL (такие карточки показываются как есть, оценка появится при пересборке).
- Удаляются столбцы `sources.format/source_url/video_path/audio_track_index`, таблицы `source_documents`, `enrichment_cache`.
- Перед созданием проверить номер на всех ветках (memory: коллизии миграций).

## Этапы

0. Замер пересборки большой книги.
1. Части: таблицы, миграция, загрузка (EPUB → главы-части), `AddPart`, видео на части.
2. Карточка на вхождение, `in_work`, `RebuildCards`, `TakeCards`, `TakeOccurrence`, `UpdateSource`, решение по слову; удаление переобработки.
3. Фильтры в чтении и генерации, API.
4. Frontend.

В master — целиком, после этапа 4.
