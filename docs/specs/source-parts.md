# Части источника, слова в работе и обновление без потерь

Продуктовые решения согласованы с Максом 14.10.2026, история обсуждения — в документе «Большие источники — проблема».

## Цель

Большой источник (книга, сериал, огромная статья) не превращается в тысячи карточек сразу и не замораживается на момент загрузки.

- Человек выбирает **кусок** источника (фильтр «Где») и **объём** работы («Взять ещё N») независимо.
- Слова, которые ещё не взяты, всегда можно пересобрать по текущей логике и знаниям, не трогая разобранное.
- Фраза для слова берётся из выбранного куска: готовишься к главе 3 — фразы из главы 3.

## Термины

- **Источник** — то, что человек изучает как целое: книга, сериал, статья, песня.
- **Часть** — кусок содержимого источника со своим документом и, возможно, своим видео: глава EPUB, раздел статьи, серия, дописанный кусок. У источника хотя бы одна часть.
- **Страница** — только подпись диапазона в фильтре «Где»: кусок части фиксированного размера `WORDS_PER_PAGE` (250 слов документа), переводится в диапазон позиций. В анализе и хранении страниц нет.
- **Вариант** (`WordOption`) — одно вхождение слова с фразой вокруг него: лемма, POS, часть, позиция, фраза, слова фразы, оценка фрагмента. Дёшев, без AI, пересобирается целиком.
- **Карточка** (`StoredCandidate`, как сейчас) — слово, взятое в работу. На ней генерация и решения.
- **Взять** — превратить вариант в карточку.
- **Решение** — статус карточки LEARN / KNOWN / SKIP.

## Модель

### Таблицы

| Таблица | Что | Изменение |
|---|---|---|
| `sources` | источник: название, коллекция, `kind`, `role`, статус, `topic_query` | уходят `format`, `source_url`, `video_path`, `audio_track_index` |
| `source_parts` | `id`, `source_id` (CASCADE), `position`, `title`, `format`, `source_url`, `video_path`, `audio_track_index`, `created_at` | новая |
| `part_documents` | `part_id` (PK, CASCADE), `document` JSON | вместо `source_documents` |
| `word_options` | `id`, `source_id`, `part_id`, `lemma`, `pos`, фраза, позиция (+ порядковый номер блока для диапазонов), слова фразы, `score`, CEFR, zipf, `is_phrasal_verb`, usage | новая |
| `candidates` | карточки | `+ part_id` (CASCADE); позиция фразы — внутри документа части |

Карточка всегда «в работе»: отдельного флага нет, взятость — это существование карточки. Невзятое слово — это варианты без карточки той же леммы.

### Почему вариант на вхождение

Сейчас на источник одна запись на лемму с лучшей фразой из первых десяти вхождений. При фильтре «гл. 3» или «стр. 40–60» слово, встречающееся там, пропадает, если его лучшая фраза в другом месте. Если хранить каждое вхождение с оценкой фразы, выбор для любого куска — обычный SELECT: `WHERE` по части и позиции, лучшая оценка на лемму. Анализатор перестаёт выбирать лучшее вхождение и отдаёт все.

Объём: одна строка на вхождение слова выше уровня; на книгу порядка десятков тысяч строк. Индексы `(source_id, lemma)`, `(part_id, block)`.

### Домен

- `SourcePart` (entity): `has_video`, `can_polish_phrases` переезжают сюда с `Source`.
- `Source.has_video` = есть часть с видео (для списка источников).
- `WordOption` (entity, frozen).
- `Where` (value object): `parts: frozenset[int] | None` (None = все), `pages: PageSpan | None`; диапазон страниц допустим только при одной выбранной части, иначе `ValueError`.
- `CardFilter` (value object): `where: Where`, `taken_only: bool`, `sections: frozenset[CandidateSection]`.
- `document_pages` (domain service): `page_count(document)`, `range_of(document, pages) -> диапазон позиций`, `time_span(document, pages)` для подписи видео временем.
- `option_choice` (domain service): по вариантам куска выбирает лучший на лемму (минимальный `score`, ничья — раньше в тексте).
- Правило «решение ⇒ взято» соблюдается тем, что решение ставится только на карточку; отметка Known/Learn на невзятом слове сначала берёт его.

## Поведение

### Загрузка

- `FormatReader` → `KindHandler` → `SourceWriter` создаёт источник и части:
  - EPUB — часть на главу (текущий `infrastructure/epub/chapters.py`); вопрос `book.split` и создание источника на главу удаляются;
  - Markdown/HTML — часть на раздел верхнего уровня, если заголовки есть; иначе одна часть;
  - видео/SRT/YouTube/текст/песня — одна часть.
- Обработка: пересборка вариантов, затем взятие первых `cards_per_take` по сортировке по умолчанию.

### Пересборка вариантов — `RebuildOptions(source_id)`

1. Удаляет варианты источника.
2. Для каждой части анализирует её документ (`AnalyzeText` по текущему уровню, словарю, частотности) и для каждого вхождения слова выбирает и оценивает фразу вокруг него.
3. Сохраняет варианты. Леммы, по которым в источнике уже есть карточка, не сохраняются.

Анализ части — один проход spaCy по её документу. `MAX_OCCURRENCES_COMPARED` уходит: оцениваются все вхождения, поэтому выбор больше не смещён к началу текста. Время пересборки на большой книге замерить до реализации; если долго — кэшировать разбор spaCy части (не зависит от знаний и уровня).

### Взять ещё — `TakeCards(source_id, filter, sort, count)`

1. `RebuildOptions`.
2. Варианты внутри `filter.where` → лучший на лемму (`option_choice`) → **ожидаемый раздел готовой карточки** → упорядочить по ожидаемому разделу, затем `CandidateSorter` → первые `count`.

Ожидаемый раздел (`expected_section`, domain service): раздел — свойство готовой карточки, а готовая фраза — фраза после Polish.
- часть, где Polish возможен (`can_polish_phrases`): PROBABLY_KNOWN для мусора и частых слов, иначе READY — сложность исходной фразы снимет Polish;
- часть без Polish (видео): раздел исходной фразы, как у карточки.

Фильтр «Раздел» к взятию не применяется: он относится к карточкам. Polish наперёд и Polish всего источника отвергнуты (14.10.2026): фраза слова зависит от «Где», заранее пришлось бы полировать каждое вхождение.
3. Каждый — новая карточка (PENDING, `part_id`, фраза и позиция варианта, медиа-таймкоды по `time_of`). Варианты этих лемм удаляются.

Генерации нет. `count` по умолчанию — настройка `cards_per_take` (100).

Точечное взятие: `TakeWord(source_id, lemma, pos, where)` — тот же шаг 2–3 для одной леммы.

### Обновление — `UpdateSource(source_id, scope)`

- `REMAINING`: `RebuildOptions`. Карточки не трогаются.
- `REMAINING_AND_OPEN`: `RebuildOptions` по анализу, в котором леммы открытых карточек (PENDING) не исключаются; для каждой открытой карточки лучший вариант её леммы **в её части**:
  - фраза та же — карточка без изменений;
  - фраза другая — новые фраза, позиция, слова; результаты генерации карточки, зависящие от фразы (polish, meaning, TTS, media), удаляются; генерация подхватит их как недостающие;
  - вариантов нет (слово больше не подходит) — карточка удаляется.
  Затем варианты лемм открытых карточек удаляются. Отказ, если у источника есть активные задания генерации.
- Карточки с решением не трогаются никогда.

`ReprocessSource`, `GetReprocessStats`, `ReprocessModal` и кэш обогащения (`enrichment_cache`) удаляются: решения больше не теряются, сгенерированное сохраняется на неизменённых карточках.

### Дописать часть — `AddPart(source_id, input, title?)`

То же чтение входа, что у загрузки; новая часть в конец (`position = max + 1`), название по умолчанию «Part N». Затем `RebuildOptions`. Карточки не берутся.

### Фильтры и чтение

- `GetSource(source_id, sort, filter)`: карточки в `where` + (если не `taken_only`) лучший вариант на лемму для невзятых слов в `where`; раздел живой, как сейчас; `filter.sections` применяется во всех сортировках, отображение разделов в списке — как в `candidate-sections.md`.
- `GetSourceDocument(part_id | where)`: документ выбранной части, подсветка — карточки и (если не `taken_only`) варианты.
- `GetGenerationStatus` / `RunGeneration(source_id, kind, scope, sort, filter)`: работают по тому, что проходит `filter`. С выключенным `taken_only` невзятые слова куска сначала берутся (`TakeCards` без лимита), затем генерируются — генерировать можно только карточки. Счётчики меню считают и невзятые слова как MISSING.
- Прогресс источника (`DecisionProgress`): «разобран», когда в источнике нет невзятых Ready-вариантов и все Ready-карточки решены. Внутри источника — прогресс по Ready-карточкам.

### Генерация и видео

- `GenerationTarget.applies_to` и `blocker` принимают часть карточки, не источник.
- Медиа: `video_path`, формат и дорожка — с части карточки; файлы — `media_root/<source_id>/<candidate_id>_*` как сейчас.
- Скачивание YouTube и очистка — на уровне части.

## API (кратко)

- `GET /sources/{id}?sort=&parts=&pages=&taken_only=&sections=` — деталь + `parts: [{id, title, position, page_count, has_video}]`.
- `POST /sources/{id}/take` `{count, filter, sort}`; `POST /sources/{id}/take-word` `{lemma, pos, filter}`.
- `POST /sources/{id}/update` `{scope}`.
- `POST /sources/{id}/parts` — дописать часть.
- `GET /sources/{id}/generation`, `POST .../generation/{kind}` — принимают `filter`.
- Удаляются `/reprocess`, `/reprocess-stats`.

## Frontend

- Шапка ревью: меню фильтра (секции «Где» / «В работе» / «Раздел»), ↻ «Обновить» рядом с ✨ (тот же двухуровневый `Menu`, тексты временные: Remaining words / Remaining words and open cards).
- Внизу списка — «Take N more · ~M left».
- `SourceRow`: Reprocess → «Update» с теми же двумя пунктами; без модалки.
- «Add part» — открывает форму добавления (место кнопки решим при реализации).
- Настройка `cards_per_take` в Settings рядом с `images_per_source`.
- Фронт ничего не вычисляет: страницы, разделы, «осталось» приходят с backend.

## Миграция 0049

- `source_parts`: по одной части на источник (`position=0`, `title` = название источника, формат и видео — из `sources`).
- `part_documents` из `source_documents` по `part_id` новой части.
- `candidates.part_id` = единственная часть источника; позиции не меняются.
- Удаляются столбцы `sources.format/source_url/video_path/audio_track_index`, таблицы `source_documents`, `enrichment_cache`.
- Существующие карточки остаются карточками (все «в работе»); варианты появятся при первом «Обновить» или «Взять ещё».
- Проверить номер на всех ветках перед созданием (см. memory про коллизии).

## Вне задачи

- Когда Learn считается знакомым (через Anki) — отдельная фича.
- Универсальная кнопка генерации — отдельная задача; здесь меню ✨ только учитывает фильтр.
- Быстрый рендер огромного текста в правой панели — с фильтром «Где» показывается только выбранная часть; виртуализация отдельно.
