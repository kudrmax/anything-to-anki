# Модель документа: вопросы на обсуждение

Места, где при реализации ТЗ (`source-document-model.html`) пришлось выбирать самому. Ничего здесь не считается решённым, пока не обсуждено.

## 1. Виртуальная точка для spaCy в песнях

**Что сделано.** В построчном абзаце (песня) строка, которая по прежней проверке заканчивает предложение, получает точку только в тексте для spaCy. В документ и во фразу точка не попадает: её токен не входит в позиции.

**Почему.** Без точки spaCy хуже разбирает строку. Пример «Hello darkness…»: старый пайплайн давал для `vision` фразу «Because a vision softly creeping», а новый без точки — три строки подряд. С точкой разбор совпадает со старым.

**Сомнение.** Это выглядит как хардкод, то есть подгонка текста под парсер.

**Варианты:**
1. Оставить точку только для парсера, как сейчас.
2. Передавать spaCy только границу предложения, без точки (было до этой правки), и принять более длинные фразы в песнях.
3. Искать другой способ улучшить разбор строки без пунктуации.

## 2. Строки абзаца склеиваются переносом, а не пробелом

**Что сделано.** При анализе строки абзаца и пункта списка склеиваются через `\n`, как в старом `cleaned_text`. В ТЗ было «через пробел»; ТЗ поправлено. На экране строки по-прежнему идут через пробел.

**Почему.** С пробелом субтитры давали мусорных кандидатов («Ew», «Heh», «Mm-hm», «-look out») и теряли нормальных. С переносом отчёт «старый против нового» совпал на 11 873 из 11 877 фраз.

**Сопутствующее.** Многострочная реплика субтитров теперь несколько строк с одним временем, а не одна строка через пробел (тоже поправлено в ТЗ).

## 3. Повторяющаяся фраза при переносе старых видео

На проде у кандидата «Grappling hook!» (Gravity Falls) фраза встречается в тексте дважды. Экран подсвечивает первое вхождение без учёта регистра (внутри «And I will have a grappling hook!»), а кадр и аудио нарезаны по настоящей реплике на 19:03.

**Варианты для переноса:**
1. Первое вхождение, как подсвечивает экран сейчас. Тогда по кнопке Regenerate media кадр поедет не туда.
2. Вхождение, время которого совпадает с уже нарезанным медиа. Тогда подсветка на экране сдвинется на правильную реплику.

## 4. Подсветка при пересечении target'ов

Когда подсветки target'ов пересекаются, остаётся та, что начинается раньше. При одинаковом начале остаётся более длинная: «give up», а не «give». Раньше приоритет был у точного совпадения по `surface_form`. С позициями совпадения точные все, поэтому правило пришлось выбрать заново.

## 5. Добавление слова: слово должно быть внутри выделенной фразы

Раньше можно было отправить слово, которого нет в выделенном фрагменте, и кандидат всё равно создавался. Теперь это ошибка: target ищется внутри фразы, иначе у него нет позиции. Через UI так не сделать (слова выбираются из самой фразы), но поведение API изменилось.

## 6. Ввод в одно поле: что считается путём к файлу

Одна строка, которая начинается со схемы `http(s)://`, — ссылка. Одна строка, которая после разворота кавычек и `~` начинается с `/`, — файл, даже несуществующий: опечатка в пути даёт «файл не найден», а не добавляется как текст. Всё остальное — текст.

## 7. Значки и подписи в списке источников

Оставлены как были: книга и субтитры без видео показываются как «Text», песня — как «Lyrics». Появился вид `book`, но отдельного значка для книги нет.

## 8. Найденный баг: `surface_form` у разорванных фразовых глаголов

`surface_form` разорванного фразового глагола склеен из токенов через пробелы (`'take one item \n from the gift shop , \n on'`). Поэтому экран не находит его в тексте: на проде 5 таких target'ов не подсвечиваются, ещё 13 подсвечены в другом месте текста. В новом пайплайне позиции берутся из токенов, так что у новых и переобработанных источников этого нет. Само поле `surface_form` не менялось (оно идёт в карточки).
