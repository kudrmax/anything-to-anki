# Разделы карточек: Ready / Extra / Probably known

Решения согласованы с Максом 14.10.2026.

## Цель

Карточка — фраза, где незнакомо только target. Экран разбора явно делит карточки:

1. **Ready** — кроме target, во фразе нет незнакомых слов.
2. **Extra new words** — во фразе есть ещё незнакомые слова.
3. **Probably known** — частые слова и мусор (как сейчас низ списка).

Пользователь разбирает Ready и переходит к другому источнику. Extra доступен, но приложение его не навязывает.

## Поведение

- Разделы есть в сортировках Relevance и Key words. В Text order — нет, порядок текста.
- Внутри раздела — прежняя сортировка; в Extra меньше лишних слов — выше. Разобранные — ниже неразобранных своего раздела.
- Probably known свёрнут, показывается по клику на заголовок раздела.
- Счётчик в шапке — только Ready: `разобрано / всего Ready`.
- Ready разобран — короткая надпись «Готово», без ссылок и кнопок.
- Источник считается разобранным (статус в списке), когда разобраны все карточки Ready.
- Подчёркиваний лишних слов во фразе нет.

## Отметка непонятного слова

Через флажок (Report). Причина «More than one unknown word» включает выбор слов: слова фразы становятся кликабельными, пользователь отмечает непонятные и отправляет жалобу.

- Отмеченные слова (их леммы) попадают в список **Unknown words**.
- Все фразы с этими словами во всех источниках уходят в Extra.
- Жалоба сохраняется как раньше.

## Список Unknown words

Пара к Known words: в настройках, со списком, поиском и удалением.

- Слово не может быть в обоих списках: добавление в один убирает из другого. Если всё же оказалось в обоих — побеждает Unknown.
- Из Unknown words карточки **никогда** не создаются.
- Список участвует везде, где раньше участвовал Known: обработка источников, подсчёт незнакомых слов во фразе, разделы, выбор слов для стартового теста, тематические источники, статистика повторной обработки, калибровка порога частоты (отметка Unknown — решение «не знаю»).

### Единая точка знаний о словах

`UserVocabulary` (application) — единственный, кто обращается к хранилищам Known и Unknown. Все use case'ы спрашивают «знает ли пользователь слово» и отмечают слова только через неё:

- `snapshot()` → `Vocabulary` (domain value object): `is_known(lemma)`, `is_unknown(lemma)`; Unknown побеждает;
- `mark_known(lemma, pos)` — убрать из Unknown, добавить в Known;
- `mark_unknown(lemma)` — убрать из Known, добавить в Unknown;
- `forget_known(lemma, pos)`, удаление и списки для настроек.

Прямое использование `KnownWordRepository` / `UnknownWordRepository` вне `UserVocabulary` и `container.py` запрещено архитектурным тестом.

## Живой пересчёт

Раздел карточки вычисляется при каждом чтении, по текущим спискам слов. Он меняется:

- после Know/Learn и других отметок слов — фразы, где помехой было только это слово, переходят в Ready;
- после отметки Unknown — фразы с этим словом уходят в Extra;
- после смены фразы (Polish, отмена Polish, ручная правка, смена границ, пример как фраза) — слова фразы разбираются заново. Раньше счётчик оставался от исходной фразы — это баг.

### Данные

У карточки хранятся слова её фразы (кроме target): `PhraseWord(lemma, rare)`, где `rare` — слово выше уровня пользователя и не частое. И текст, по которому слова посчитаны.

Слово лишнее (незнакомое), если оно в Unknown words, или `rare` и его нет в Known words.

Если текст фразы карточки не совпадает с текстом, по которому посчитаны слова, слова пересчитываются при чтении и сохраняются. Так одно место ловит все способы сменить фразу, а старые карточки получают слова при первом открытии.

`fragment_unknown_count` и `fragment_purity` у карточки удаляются: это устаревающие производные. В снимке жалобы число лишних слов остаётся (живое на момент жалобы).

## API

- `StoredCandidateDTO.section`: `ready | extra | probably_known`.
- `SourceDetailDTO`: `ready_total`, `ready_reviewed`.
- Жалоба принимает `unknown_words` — диапазоны символов внутри фразы карточки; леммы определяет backend.
- Unknown words: список, удаление (как Known words).
- Статистика: `unknown_word_count`.
