Модель фразы карточки

Фраза карточки описана одним объектом: текст как есть, слова этого текста по символам и target — номера слов. Подсветка, cloze, выбор слов, разделы Ready / Extra и экспорт берут всё из него. Поверх — разделы карточек из candidate-sections.md.

Версия 1

00Принцип

  • Текст фразы — главный. Хранится как есть: с запятыми, кавычками, переносами строк, ручной правкой. Из слов он не собирается.
  • Слова — места в тексте. Слово — символы [start, end) текста и то, что о нём знает разбор языка. Пунктуация остаётся в тексте и словом не является.
  • Target и cloze — номера слов этой фразы. Ни один экран и ни одна операция не ищут target в тексте заново.
  • Новый текст — новая фраза. Polish, ручная правка, новая граница: текст разбирается, target находится один раз, при создании фразы.
  • Что пользователь знает — не часть фразы. Фраза хранит свойства слов (уровень, частотность). Новое ли слово, решается при чтении по текущим Known / Unknown words, уровню и порогу частоты.

01Термины

ТерминЧто это
PhraseФраза карточки: text, words, target.
WordСлово фразы: start, end (символы текста), lemma, level (CEFR или нет), zipf, content.
Слово в текстеНепрерывная последовательность букв, цифр, апострофов и дефисов: don't, well-known, ’cause — одно слово. То же правило, что сейчас у выделения target в Quick Add.
contentСлово может быть незнакомым: не служебное слово (the, of) и не имя собственное. Служебные и имена в разделах не участвуют, но их видно и можно выбрать.
targetНомера слов target по порядку. Разорванный фразовый глагол gave it up — номера gave и up, без it.
Фраза из книгиsource_phrase — фраза, вырезанная из документа (или пример, тема, сохранённая фраза — у них нет места в документе).
Переписанная фразаpolished_phrase — после Polish или ручной правки. Активная, пока пользователь её не отменил.
Показанная фразаПереписанная, если она есть и не отменена; иначе фраза из книги. Как сейчас card_phrase.

03Сущности

@dataclass(frozen=True)
class Word:
    start: int            # символы текста фразы, [start, end)
    end: int
    lemma: str            # словарная форма: "scattered" → "scatter"
    level: CEFRLevel | None
    zipf: float
    content: bool         # может быть незнакомым

@dataclass(frozen=True)
class Phrase:
    text: str
    words: tuple[Word, ...]
    target: tuple[int, ...]   # номера слов, по порядку, не пусто

    def target_text(self) -> str: ...      # "gave up" — как написано во фразе
    def other_words(self) -> tuple[Word, ...]: ...   # все, кроме target

Инварианты, проверяются при создании: слова не пересекаются и идут по порядку, каждое лежит внутри текста, target не пуст и ссылается на существующие слова.

Карточка (StoredCandidate) вместо context_fragment, polished_fragment, surface_form, phrase_words хранит:

source_phrase: Phrase
polished_phrase: Phrase | None
polish_reverted: bool
phrase_position: DocumentPosition | None   # где source_phrase стоит в документе; без изменений
cloze: CandidateCloze | None               # hidden_word_indices — номера слов показанной фразы

@property
def phrase(self) -> Phrase: ...            # показанная фраза

lemma, pos, уровень и частотность target остаются у карточки: это то, что карточка учит, а не часть фразы.

04Разделы Ready / Extra

Доменный сервис по показанной фразе и Vocabulary (Known + Unknown words):

new_words(phrase, vocabulary, user_level, frequent_zipf) -> list[str]
# слово из other_words() новое, если
#   его лемма в Unknown words, или
#   content и лемма не в Known words и level выше уровня пользователя и zipf ниже порога
  • Ready — новых слов нет; Extra — есть; Probably known — как сейчас, по самому target.
  • Смена уровня или порога частоты в настройках сразу пересчитывает разделы: свойства слов хранятся, а не готовое «редкое / не редкое».
  • Флажок «More than one unknown word» отдаёт номера выбранных слов показанной фразы. Их леммы идут в Unknown words. Разбор языка при этом не нужен — леммы уже в фразе.

05Порты и use case'ы

PhraseReader (application)

Единственное место, где текст превращается во фразу. Через порт TextAnalyzer (spaCy) получает токены, собирает слова по правилу «слово в тексте», лемму, уровень и частотность берёт из токенов слова. Два способа указать target:

МетодКогдаКак ставится target
read(text, target_spans)Пользователь или источник указал target символами: выделение в Quick Add, «Добавить слово», **bold** в примере и теме, место target в документеСлова, которые попадают в эти символы
read_for(text, lemma)Текст без указанного target: Polish, ручная правка, новая границаСлова, чьи леммы дают лемму карточки по порядку (give up → gave … up). Первое такое вхождение. Не нашлось — TargetNotInPhraseError

Use case'ы, которые меняются

Кто только читает фразу

  • Anki, recognition: <b> вокруг слов target по символам. Cloze: {{c1::…}} вокруг скрытых слов по символам, текст между ними — как есть.
  • TTS, meaning, Polish (контекст), жалоба (снимок), кэш обогащений: phrase.text.
  • Экран источника: подсветка target — из phrase_position и символов target внутри source_phrase; полоса фразы — из phrase_position.

06API и фронт

"phrase": {
  "text": "A sudden gale scattered the gulls.",
  "words": [[0, 1], [2, 8], [9, 13], [14, 23], [24, 27], [28, 33]],
  "target": [3]
},
"source_phrase": { ... }   // для сравнения Polish, если есть переписанная
  • Фронт режет текст по символам слов и рисует: target, скрытые cloze, выбор слов во флажке и в «Добавить слово». Своих правил деления на слова и поиска target у фронта нет.
  • Леммы и уровни слов на фронт не уходят — не нужны.
  • Подсветка target в meaning и примерах (текст от AI) остаётся как сейчас: это не фраза карточки.

07Хранение

  • candidates.source_phrase, candidates.polished_phrase — JSON: {"text", "words": [[start, end, lemma, level, zipf, content], …], "target": [i, …]}.
  • Удаляются: context_fragment, polished_fragment, surface_form, target_position, has_custom_context_fragment, phrase_words.
  • card_reports не меняется: снимок хранит текст.

08Перенос старых карточек

Ревизия Alembic, выполняется при make up. Ей нужен разбор языка, поэтому она вызывает PhraseReader приложения. После применения на проде и dev тело ревизии очищается, как у ревизии переноса на документы.

  1. source_phrase: текст = context_fragment. Target — символы target_position внутри фразы, если оно есть; иначе read_for по лемме.
  2. polished_phrase: текст = polished_fragment, target — read_for. Не нашёлся — переписанная фраза не переносится, карточка показывает фразу из книги (так же поступает Polish, когда AI теряет target).
  3. Cloze: старые номера — номера слов по пробелам; переводятся в новые через символы. Если показанная фраза у карточки не переносится, разметка строится заново.

Перед вливанием — прогон на копии прод-базы и отчёт: сколько карточек получили target каждым способом, у скольких переписанная фраза не перенеслась, у скольких сменилась разметка cloze, примеры каждого случая.

09Сохраняется

  • Всё, что видно в ревью сейчас: подсветка target, Polish с сравнением и отменой, «Polish again», ручная правка двойным кликом, смена границы, «Добавить слово», «Use as phrase», cloze с подсказками, жалобы, Quick Add, темы.
  • Экспорт в Anki: те же поля и тот же вид <b> и cloze. Пробелы и переносы фразы в cloze-тексте больше не схлопываются в один пробел.
  • Ручная правка не сбрасывает meaning и TTS; Polish и отмена сбрасывают — как сейчас.
  • Время видео, кадры и аудио — по phrase_position, как сейчас.

11Этапы

  1. Domain: Word, Phrase, сервис новых слов. PhraseReader и правило «слово в тексте».
  2. Обработка источника строит фразы из разбора документа; все use case'ы из раздела 05 переходят на Phrase.
  3. Экспорт, TTS, meaning, Polish, жалобы — на phrase.text и номера слов.
  4. API и фронт: рисование по символам, удаление фронтовых правил поиска target.
  5. Разделы Ready / Extra и флажок — на новой фразе; phrase_words удаляется.
  6. Ревизия переноса, прогон и отчёт на копии прод-базы, очистка тела ревизии после применения.
