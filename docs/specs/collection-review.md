# Разметка коллекции

Issue: https://github.com/kudrmax/anything-to-anki/issues/4

## Принцип

**Разметка коллекции и разметка источника — одна и та же функциональность, один код.**

Экран разметки, секции, сортировка, прогресс, статус и кнопка Continue / Review работают
не на «источник», а на **набор источников**. Источник — набор из одного источника.
Коллекция — набор из всех источников её поддерева, на любой глубине вложенности.

Веток вида «если коллекция — так, если источник — иначе» нет ни в backend, ни во frontend.
Если завтра меняется правило сортировки или секций, оно меняется в одном месте и сразу
действует и для источника, и для коллекции.

## Термины

- **Набор (`SourceScope`)** — какие источники открыты. Это существующий value object
  `SourceScope` (ALL / UNSORTED / COLLECTION). В него добавляется вид **SOURCE(source_id)**:
  набор из одного источника. Так «источник» и «коллекция» становятся одним понятием.
- **Источники набора** — `SourceScopeResolver.sources(scope)`. Для SOURCE — один источник.
  Для COLLECTION — источники поддерева, как сейчас. **Порядок источников набора — ровно
  тот, что отдаёт `SourceScopeResolver.sources(scope)`.** Своей логики порядка у разметки
  нет: когда у коллекций появится сортировка, она поменяется там, и разметка (тексты
  справа, порядок «по тексту») подхватит её сама.
- **Разметка набора** — список карточек всех источников набора, разложенный по секциям
  и отсортированный существующим `CandidateSorter.arrange`.

## Что меняется

```
                 SourceScope (SOURCE | COLLECTION | …)
                               │
                 SourceScopeResolver.sources(scope)
                               │  [Source, …] в порядке набора
        ┌──────────────────────┼─────────────────────────┐
        ▼                      ▼                         ▼
 ReviewCards.of_sources   ReviewProgress (уже     Документы источников
        │                 принимает список id)    (по одному на источник)
        ▼                      │                         │
 CandidateSorter.arrange       ▼                         ▼
 (без изменений)          статус набора            правая панель:
        │                 + кнопка                 тексты подряд,
        ▼                 Continue / Review        заголовок = источник
 секции + карточки
```

### Domain

- `SourceScope`: вид `SOURCE(source_id)`, его строковая форма и разбор.
- Статус набора. Сейчас `derive_review_status(stored: SourceStatus, progress)` берёт
  статус одного источника. Добавляется одна функция «сохранённый статус набора» из
  статусов его источников: есть обработанный (DONE) → DONE; иначе все источники в ERROR
  (и набор не пуст) → ERROR; иначе NEW. Пустая коллекция — NEW. Для набора из одного источника она возвращает его статус. Дальше
  `derive_review_status`, `can_review`, `review_fraction`, `progress_caption` работают
  как сейчас, на суммарном прогрессе набора. Это та же логика, что у источника.
- Хронологический порядок (`sort_chronologically`): ключ начинается с места источника
  в наборе, потом место фразы в документе. Для одного источника первая часть ключа
  одинакова у всех карточек, порядок не меняется.
- Остальная сортировка и секции не меняются. «Слово» по-прежнему существует отдельно
  в каждом источнике: одна лемма из двух источников — два слова. Их карточки стоят там,
  куда их ставит та же сортировка; после решения по одному у другого появляется
  пометка «решено в другом источнике», как сейчас.

### Application

Каждый use case экрана разметки принимает `SourceScope` вместо `source_id`:

- **Детали разметки** (сейчас `GetSourcesUseCase.get_by_id`): карточки набора через
  `CardViews.listed(scope, order)` → `ReviewCards.of_sources(ids)` →
  `CandidateSorter.arrange`. `CardViews.listed` и `ReviewCards.of_source` переводятся
  на список источников (новый код, а не вторая копия: старые версии по одному id
  удаляются). Заголовок — название источника или путь коллекции
  (`SourceScopeResolver.title`). Статус, прогресс, `learn_count` — по набору.
- **Документ**: список документов источников набора в порядке набора, у каждого
  `source_id`, заголовок и подсветки его карточек. Источник без документа в список
  не входит.
- **Генерация** (статус, запуск, отмена): существующие правила применяются к каждому
  источнику набора по очереди. Источник, который сейчас не может её запустить (занят
  операцией, видео не скачано, вид генерации к нему не относится), пропускается,
  остальные ставятся в очередь. Ошибка — только если не запустился ни один. Статус
  генерации набора — сумма статусов источников.
- **Занятость (`busy_with`)** переходит к карточке: карточка заблокирована, если занят
  её источник. Остальные карточки набора доступны. Для одного источника это то же, что
  сейчас (все карточки из одного занятого источника).
- **Скачивание видео**: для всех источников набора, у которых есть видео и оно не скачано.
- **Своя карточка выделением текста**: выделение принадлежит документу конкретного
  источника, карточка добавляется в этот источник. Use case остаётся по `source_id`.
- **Экспорт** с экрана разметки ведёт на экспорт набора: существующий экспорт по scope.
- Список коллекций (`ListCollectionsUseCase`) отдаёт для каждой коллекции то же, что
  нужно строке источника для прогресса и кнопки: статус набора, `can_review`,
  `review_fraction`, `progress_caption`. Считается теми же функциями, что у источника.

### DTO

- У каждой карточки появляется `source_id` (и то, что нужно для её медиа и видео-плеера:
  медиа и видео живут у источника карточки, а не у экрана).
- Всё, что сейчас в деталях источника относится к одному источнику (kind, has_video,
  video_downloaded, can_polish_phrases, busy_with, processing_stage, error_message),
  либо считается по набору той же функцией, либо уходит к карточке / к документу
  источника. Полей, которые есть только у источника или только у коллекции, нет.

### API

Эндпоинты экрана разметки принимают scope вместо `source_id`: детали, кандидаты,
документ, генерация (статус / запуск / отмена), скачивание видео. Для источника
передаётся scope вида SOURCE. Старые эндпоинты `/sources/{id}/…`, которыми пользуется
только экран разметки, заменяются, а не дублируются.

### Web

- Один `ReviewScreen` и один `useReview(scope)`. Маршруты `/sources/:id/review` и
  `/collections/:id/review` открывают его с разным scope; больше нигде вид scope не
  проверяется.
- Медиа-URL и аудио строятся от `source_id` карточки.
- Правая панель: тексты источников набора подряд, у каждого заголовок с названием
  источника. У одного источника — один заголовок.
- Строка коллекции на экране Sources показывает прогресс, подпись и ту же кнопку,
  что строка источника: один компонент, который выбирает кнопку по статусу набора.
  У разметки это Review / Continue / Open. Если статус набора NEW или ERROR, та же
  кнопка показывает Process / Retry и обрабатывает необработанные источники набора
  через существующий `ProcessSources.pending_in(scope)`. Генерации тем
  (awaiting generation) у коллекции нет, эта часть кнопки у неё не появляется.
- «All sources» получает ту же кнопку разметки, что коллекция (это тоже набор).
- «Unsorted» — служебная папка, в идеале пустая, она не для разметки. Разметка для неё
  запрещена целенаправленно: правило в domain (`can_review` набора вида UNSORTED —
  False), backend отвечает отказом, кнопка не показывается. Это осознанное исключение
  по решению Макса.
- После решения по карточке экран обновляется так же, как сейчас. Карточку той же
  леммы из другого источника (пометка «решено в другом источнике») подтягивает то же
  обновление списка; отдельного механизма нет.

## Что сохраняется

Всё, что умеет разметка источника сегодня: три порядка сортировки, секции и
«✨ для Ready», генерация по секциям, своя карточка выделением, видео и аудио, отчёты
о карточках, переход к экспорту, возврат на Sources. Для одного источника экран
выглядит и ведёт себя как сейчас, кроме заголовка над текстом в правой панели.

## Не делаем

- Не храним новый «счёт» карточки: сортировка уже считается по признакам, которые
  не зависят от источника, и просто применяется к общему списку.
- Не группируем карточки одной леммы из разных источников.
- Не трогаем Rebuild / Refresh и операции над источниками в меню Sources.
- Не делаем ленивую загрузку и лимиты для больших коллекций. Проверяем скорость на
  копии prod-базы на самой большой коллекции; если медленно, приходим с цифрами.

## Решения, принятые мной (на вето)

1. Порядок источников — `SourceScopeResolver.sources(scope)` (решение Макса).
2. Статус набора: DONE, если есть хоть один обработанный источник; ERROR, если все
   источники в ошибке; иначе NEW.
3. Хронологический порядок в коллекции — по источникам, внутри источника по тексту.
4. Заголовок над текстом показывается и у одного источника (одна логика).
5. Лемма из нескольких источников не склеивается (переиспользуем сортировку как есть).
6. Генерация на коллекцию пропускает источники, которые сейчас не могут её запустить.
7. Занятость — у карточки: блокируются только карточки занятого источника (решение Макса).
8. Строка коллекции в статусе NEW/ERROR показывает Process / Retry на необработанные
   источники (тот же компонент кнопки).
9. Без лимитов и ленивой загрузки; скорость проверяю на копии prod-базы.
