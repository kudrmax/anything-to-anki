# Dictionaries

The app reads dictionary data from the folder set in `DICTIONARIES_DIR` in `.env`. On every `make up`, it builds a fast SQLite cache from that folder: `$DICTIONARIES_DIR/.cache/dict.db`.

## What the dictionaries give

| Data | Used for | Without it |
|---|---|---|
| CEFR levels (`cefr/*.json`) | Deciding which words are above your level; the level shown on cards; calibration | The app falls back to its built-in CEFR list ([cefrpy](https://pypi.org/project/cefrpy/)), which knows fewer words. Calibration has no words |
| Pronunciation audio (`audio.json`) | **US / UK** buttons on cards, and the `AudioTargetUS/UK` Anki fields | No dictionary pronunciations. TTS still works |
| IPA (`ipa.json`) | Transcription from the dictionary | The AI transcription is still shown |
| Usage labels (`usage.json`) | Labels such as *formal* and *informal*; the [usage priority](../guide/vocabulary.md#word-order-in-review) | All words count as neutral |

Word frequency, phrasal verbs and the English language model come with the app; they don't need dictionaries.

## Getting the data

### Ready-made dictionaries

The ready-made data lives in the [anything-to-anki-dicts](https://github.com/kudrmax/anything-to-anki-dicts) repository, in the `unified/` folder. **Access to it is restricted, so you most likely can't download it.** If you have access:

```bash
git clone https://github.com/kudrmax/anything-to-anki-dicts.git
```

Then set `DICTIONARIES_DIR` to the absolute path of its `unified/` folder.

### Building your own

If you don't have access, build the dictionaries from the original sources with [anything-to-anki-parsers](https://github.com/kudrmax/anything-to-anki-parsers). It has converters for four sources:

| Source | Raw file | Output |
|---|---|---|
| Oxford 5000 | `raw/oxford5000.csv`: columns `word`, `type`, `cefr` | `unified/cefr/oxford.json` |
| EFLLex | `raw/efllex.tsv`: columns `word`, `tag`, `level_freq@a1` … `level_freq@c1` | `unified/cefr/efllex.json` |
| Kelly list | `raw/kelly.csv`: columns `Word`, `Part of Speech`, `CEFR` | `unified/cefr/kelly.json` |
| Cambridge Dictionary | `raw/cambridge.jsonl`: one JSON object per word | `unified/cefr/cambridge.json`, `audio.json`, `ipa.json`, `usage.json` |

1. Clone the parsers:

   ```bash
   git clone https://github.com/kudrmax/anything-to-anki-parsers.git
   cd anything-to-anki-parsers
   ```

2. Get the raw files you can and put them into `raw/` under the names above. You need at least one. The converters need only Python 3.10+.
3. Convert:

   ```bash
   make convert-all
   ```

   `convert-all` stops at the first missing raw file. If you have only some of them, run the converters one by one (see the parsers' `Makefile`).
4. Set `DICTIONARIES_DIR=/absolute/path/to/anything-to-anki-parsers/unified` in the app's `.env`, then run `make dict-rebuild` and `make up` in the app.

Only the Cambridge data has pronunciations, IPA and usage labels. Without it, the app works with the limits listed [above](#what-the-dictionaries-give).

### Without dictionaries

You can run the app with an empty folder:

```bash
mkdir -p ~/anything-to-anki-dicts-empty
```

```bash
DICTIONARIES_DIR=/Users/you/anything-to-anki-dicts-empty
```

Everything works with the limits listed [above](#what-the-dictionaries-give). Add dictionaries later and run `make dict-rebuild`. Then use **Find words again** on your sources to apply the new levels.

## Format

You can also write your own dictionary files. Every file is optional.

```
$DICTIONARIES_DIR/
├── cefr/               # any number of files; the app votes between them
│   ├── cambridge.json
│   ├── oxford.json
│   ├── efllex.json
│   └── kelly.json
├── audio.json
├── ipa.json
├── usage.json
└── .cache/             # generated by the app
    └── dict.db
```

All keys are lemmas (dictionary forms) in lower case.

### CEFR (`cefr/*.json`)

Each file is one source of CEFR levels.

```json
{
  "meta": {
    "name": "My Dictionary",
    "priority": "normal"
  },
  "entries": {
    "example": {
      "noun": {"B1": 1.0}
    },
    "run": {
      "verb": {"A2": 3.0, "B1": 7.0}
    }
  }
}
```

- `meta.name` (required): the source's name, shown in the CEFR tooltip on cards.
- `meta.priority` (required): `"high"` or `"normal"`. High-priority sources are asked first; if one of them knows the word, its level wins. Otherwise all normal sources, plus the built-in cefrpy, vote.
- `entries`: `{lemma: {part of speech: {level: weight}}}`.
  - Parts of speech: `noun`, `verb`, `adjective`, `adverb`, `phrasal verb`, `exclamation`, `modal verb`, `preposition`, `determiner`, `pronoun`, `conjunction`, `number`, `abbreviation`, `other`.
  - Levels: `A1`, `A2`, `B1`, `B2`, `C1`, `C2`.
  - Weights are raw numbers and are normalised when the cache is built: `{"A2": 3.0, "B1": 7.0}` becomes 30% A2 and 70% B1. A source with one level per word uses `{"B2": 1.0}`.

### Audio (`audio.json`)

```json
{
  "example": {
    "us": "https://example.com/us_pron.mp3",
    "uk": "https://example.com/uk_pron.mp3"
  }
}
```

`us` and `uk` are URLs of audio files; both are optional. The app downloads the files when it generates pronunciations.

### IPA (`ipa.json`)

```json
{
  "example": {
    "us": "/ɪɡˈzæm.pəl/",
    "uk": "/ɪɡˈzɑːm.pəl/"
  }
}
```

### Usage (`usage.json`)

```json
{
  "example": {
    "noun": ["formal"]
  },
  "gonna": {
    "verb": ["informal"]
  }
}
```

`{lemma: {part of speech: [labels]}}`. The labels are free-form strings. The app groups the known ones (`formal`, `informal`, `specialized`, `disapproving`, `approving`, `humorous`, `old-fashioned`, `offensive`, `literary`, …) into the [usage priority](../guide/vocabulary.md#word-order-in-review) groups.

## The cache

| Command | What it does |
|---|---|
| `make dict-update` | Rebuilds the cache if any JSON file changed. `make up` and `make test` run it |
| `make dict-rebuild` | Rebuilds the cache from scratch |

After you change the dictionaries, existing sources keep their old levels. Run **Find words again** on them to apply the new data.
