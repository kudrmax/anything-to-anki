# Вкладка Usage — статистика AI-токенов

## Цель

Видеть, сколько токенов уходит на AI: всего, по функциям, по дням/часам.

## Данные

До этой фичи токены нигде не сохранялись (только лог `ai_proxy`), а `tokens_used`
не учитывал кэш-токены. Статистика копится с момента выкатки.

- `ai_proxy` отдаёт в каждом ответе `usage`: input, output, cache read, cache creation.
- Каждый вызов AI пишется в таблицу `ai_usage`: время, функция, модель, четыре
  счётчика токенов, число результатов (items), длительность, успех.
- Функции (`AIFeature`): meaning batch, meaning single, follow-up, phrase polish,
  topic targets. Follow-up получил свой метод порта `AIService.generate_follow_up`.

## Запись

`HttpAIService` получает порт `AIUsageRecorder` и записывает каждый вызов —
успешный и упавший (упавший — с нулём токенов). Запись идёт в отдельной сессии
с собственным коммитом, чтобы откат транзакции use case не терял статистику.
Ошибка записи логируется и не ломает AI-вызов.

## Агрегация

`GetAIUsageStatsUseCase.execute(period, timezone)`; period: `today | 7d | 30d | all`.
Таймзону присылает клиент (IANA), бакеты считаются в ней:
`today` — по часам, остальное — по дням, пустые бакеты заполнены нулями.

Возвращает: итоги (токены по видам, запросы, упавшие, изменение к предыдущему
такому же периоду, токенов на meaning), ряд бакетов с разбивкой по функциям,
таблицу по функциям с долей, дату начала сбора.

`GET /api/usage?period=30d&tz=Europe/Moscow`.

## Frontend

Вкладка `Usage` после Queue → `/usage`. Плитки, stacked-график на SVG в токенах
приложения с тултипом, таблица по функциям. Стоимость в $ не показываем.
