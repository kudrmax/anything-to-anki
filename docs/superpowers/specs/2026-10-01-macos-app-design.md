# macOS-приложение

Дата: 2026-10-01.

## Цель

Открывать AnythingToAnki отдельным окном из Dock, а не вкладкой браузера, и не запускать `make up` руками. Стек, две рабочие копии (dev и prod) и обновление через `git pull` остаются прежними.

Критерий успеха: клик по иконке в Dock открывает окно с интерфейсом. Если процессы не запущены, приложение само выполняет `make up`. При выходе останавливает процессы, но только те, что запустило само. Все функции web-интерфейса работают, включая выбор файла и генерацию через Claude.

## Границы

- Новый фронтенд `frontends/macos/`: тонкая оболочка из AppKit и WKWebView. Backend и web-фронтенд не меняются.
- Процессы, как и прежде, запускаются только через `make`: оболочка вызывает `make up` и `make down`.
- Не делаем: подпись и нотаризацию, песочницу, автообновление, меню в строке меню, уведомления.

## Сборка

- `make app` в любой копии собирает `AnythingToAnki.app` через `swiftc`, Xcode-проект не нужен. Собранное приложение кладётся в `~/Applications`.
- В `Info.plist` при сборке записываются:
  - путь к папке копии;
  - `PORT` из `.env` этой копии;
  - имя приложения. Для `INSTANCE_ENV_NAME=prod` имя «AnythingToAnki», для любого другого окружения добавляется суффикс, например «AnythingToAnki Dev».
- Bundle id зависит от окружения, чтобы dev и prod были разными приложениями со своими настройками окна и своим хранилищем.
- Иконка — `.icns`, собирается из одного исходного PNG в `frontends/macos/`.

## Запуск и выход

`ServerLauncher` — отдельный класс с тестами, без AppKit:

1. Проверить, отвечает ли `http://localhost:PORT`.
   - Отвечает — ничего не запускать, запомнить «процессы не наши».
   - Не отвечает — выполнить `/bin/zsh -lc 'make up'` в папке копии. Login shell нужен, чтобы `PATH` включал Homebrew и CLI `claude`, как в терминале. Запомнить «процессы наши».
2. Ждать ответа сервера с таймаутом. Если `make up` завершился с ошибкой или истёк таймаут — вернуть ошибку с последними строками вывода.
3. При выходе: если процессы наши — выполнить `/bin/zsh -lc 'make down'` и дождаться завершения. Иначе ничего не делать.

Проверка порта и запуск команд скрыты за протоколами. Поэтому логику можно тестировать без сети и без `make`.

## Окно

- Пока сервер запускается, показывается экран загрузки; при ошибке — текст ошибки, хвост вывода и кнопка «Повторить».
- После запуска WKWebView загружает `http://localhost:PORT`.
- Стандартное меню:
  - Cmd+Q — выход с остановкой процессов, как описано выше;
  - Cmd+W — прячет окно, клик по иконке в Dock возвращает его;
  - Cmd+R — перезагрузка страницы;
  - меню правки: копировать, вставить, выделить всё, отменить.
- Размер и положение окна запоминаются (`setFrameAutosaveName`).
- `<input type="file">` открывает системный диалог (`runOpenPanelWith`).
- Ссылки на другие хосты и `target="_blank"` открываются в браузере по умолчанию.
- `localStorage` хранится в собственном хранилище приложения. Настройки из браузера не переносятся.

## Claude

ai_proxy запускается через `make up` под пользователем, как и сейчас, и обращается к установленному CLI `claude` и Keychain. Приложение без песочницы, поэтому доступ к Keychain не меняется.

## Проверка

- `swift test` в `frontends/macos/`: тесты `ServerLauncher` — сервер уже запущен, запуск собственными силами, ошибка `make up`, таймаут, остановка при выходе только своих процессов. Входит в `make test-macos`.
- Ручной прогон на prod-сборке:
  - запуск с нуля;
  - запуск при работающем сервере;
  - Cmd+Q в обоих случаях;
  - добавление файла;
  - Review с клавишами;
  - генерация значения через Claude;
  - внешняя ссылка.
- Документация: раздел в `docs/running.md`, `docs/project-map.md`.
